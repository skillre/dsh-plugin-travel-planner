# 右侧栏 v6 设计（已批准 · 已实现）：按宽度重新分配版面

承接 `docs/sidebar-v5-design.md`。本文只做设计，**不动代码**；批准后再实现。
素材：你 2026-09-17 的截图（深色主题、窗口最大化）。

---

## 0. 你截图里量到的问题

以截图像素（2664×1573，约 2× 截图 → 面板约 **1332 CSS px 宽**）估算：

| 现象 | 量到的数字 | 后果 |
|---|---|---|
| 行程卡片被拉到整宽 | 卡片宽 ≈ **1150px** | 中文一行约 45 字才换行，名称在左、时长在 1500px 外、缩略图在最右，眼睛要横穿整屏 |
| 天标题挤成一行 | 一行里 10 个信息（D1/日期/星期/天标题/路名/行驶/里程/站数/待重算/提醒/序号） | 没有主次，读起来像一串标签 |
| 地图是一条横幅 | 高 ≈ 255px、宽 ≈ 1330px（≈5:1） | 面积很大但只能看个大概；**一滚动就滚走了**，读行程时看不到地图 |
| 目录与天标题重复 | 目录写 `1077.1 km / 未记录 / 市内`，天标题也写里程与站数 | 同一屏两处说同一件事，密度升高、重点变模糊 |
| 竖排空间被地图吃掉 | 地图 + 头部 + 信息行 ≈ 屏幕上半 | 首屏只看得到 2 个站点 |

一句话：**版面没有随宽度变化**——它把为 380px 侧栏设计的单列布局，原样拉伸到 1332px。

---

## 1. 目标与非目标

**目标**

- 宽面板不再拉伸正文，读起来像一份文档，而不是一张被吹大的表格。
- 地图从「顶部横幅」变成**一直在场的伙伴**：读行程时地图不会滚走。
- 天标题分两级，主行说「哪一天、从哪到哪」，事实行说数字与动作。
- 目录只做索引，不再与天标题争抢信息。

**非目标**

- 不改数据模型、不改 Host；纯 Client。
- 不改窄栏（<560px）现有形态：那里现在的布局是对的。
- 不引入第三方 UI 库。

---

## 2. 三个方案

### 方案 A：宽屏双栏 + 右侧常驻「地图 · 目录」（推荐）

```
┌ 头部（标题 / 就绪度 / ⋯）───────────────────────────────────────────────┐
│ 行程卷轴（可读宽度 760px，居中偏左）        │ 右栏（sticky，一直可见）        │
│                                           │ ┌───────────────────────────┐ │
│ ╭ D1 · 09-24 周四  北京 → 西安｜赶路 1,077km ╮│ │ 地图（高度可拖，240–380）  │ │
│ │ 行驶 12h38 · 1077 km · 2 站  [待重算][3 提醒]│ │  当天/全程 · 聚焦当前天    │ │
│ │ 12:00 ● 天安门广场            [图]        │ │ └───────────────────────────┘ │
│ │   🚗 驾车 1077.1 km · 12h38  待重算        │ │ ┌ 日期目录（自身滚动） ─────┐ │
│ ╰───────────────────────────────────────────╯ │ │ D1 09-24 ▔▔▔ 1077km      │ │
│   🛣 西安 → 成都 · 723 km  [补上时长]          │ │ D2 09-25 ⚠               │ │
│ ╭ D2 · 09-25 周五  西安 → 成都｜翻秦岭 723km ╮│ │ D3 09-26 ⚠               │ │
│ │ …                                          │ │ D4 09-27 市内            │ │
└───────────────────────────────────────────────┴──────────────────────────────┘
```

- **左列**：`minmax(0, 1fr)`，内容 `max-width: 760px`。多出来的宽度成为栏间距，不再拉长正文。
- **右列**：`clamp(320px, 34%, 520px)`，`position: sticky; top: 0`，自身上下两段——地图（`clamp(240px, 34vh, 380px)`，保留三档与拖拽把手）＋ 日期目录（`flex: 1; overflow-y: auto`）。
- 效果：**滚动行程时地图与目录钉在原处**；地图不再是首屏横幅。
- 断点：`@container (min-width: 1080px)` 进入双栏；560–1080 维持现状（单列 + 右侧目录）；<560 维持现状（地图顶部折叠 + 无目录）。

### 方案 B：单列限宽 + 顶部地图（改动最小）

保持现在的结构，只做三件事：正文 `max-width: 760px` 居中；天标题分两级；目录去掉里程/未记录文字。

- 优点：一天就能改完，风险最低。
- 缺点：**地图仍然会滚走**；宽屏两侧留白（左右各 ~280px）显得空。

### 方案 C：总览表优先（另一条路）

顶部放一张 14 行表：`日期 | 路线 | 里程 | 行驶 | 站数 | 提醒`，点行展开该天时间轴；地图放在表上方或右侧。

- 优点：「整体」最强，14 天一眼扫完，最适合规划期对账。
- 缺点：表格是「查」的界面，不是「读」的界面；会退回成 v5 之前的翻页式阅读（只是换成了展开行）；与地图联动也变弱。

## 3. 推荐方案 A 的详细规格

### 3.1 版面与断点

| 容器宽度 | 结构 | 说明 |
|---|---|---|
| < 560px | 现状 | 地图折叠在顶部（168/260/全屏），单列行程，无目录 |
| 560–1080px | 现状 + 限宽 | 单列行程（`max-width: 760px`）+ 右侧 124px 目录 |
| ≥ 1080px | **双栏** | 左：行程（≤760px）；右：地图 + 目录（sticky） |

### 3.2 天标题（两级）

```
主行：D1 · 09-24 周四   北京 → 西安｜赶路 1,077km        ← 路线/主题加粗，补充说明次要色
次行：行驶 12h38 · 1077 km · 2 站      [交通待重算] [3 提醒]  ← 数字用 chip，动作靠右
```

- 去掉天标题里的 `1/14`（目录已经表达位置）；`京港澳→京昆` 这类路名并进次行的次要文字。
- 动作按钮只在需要时出现（待重算 / 提醒），平时次行只有数字，安静。

### 3.3 行程卡片

- 卡片宽度由列宽决定（≤760px），不再依赖 `flex: 1` 撑满。
- 卡内顺序保持：名称 · 固定 · 时长 → 类别 · 地址 → 告警；缩略图与把手在右。
- 760px 下名称到时长约 600px，属于可读范围。

### 3.4 日期目录（只做索引）

```
D1  09-24  ▔▔▔▔▔  1077km     ← 有记录：强度条 + 里程
D2  09-25  ⚠               ← 未记录：一个警示点（tooltip 说明「换了城市但没有交通记录」）
D4  09-27  市内             ← 当天没有跨城
```

- 强度条保留（它是「节奏」的唯一表达）。
- 「未记录」由文字改为警示点 + tooltip，减少与天标题的重复。
- 当前天整行高亮；点击滚动到那天。

### 3.5 地图

- 位置：宽屏在右栏顶部（sticky）；中/窄屏维持现状。
- 高度：`clamp(240px, 34vh, 380px)`，保留三档与拖拽。
- 全程模式下当前天满色、其余淡化（v5.0 已实现）；「聚焦当前天」保留。
- 右栏高度不足时（窗口很矮），目录先滚动，地图可折叠成 120px 的迷你态（自动，不需要用户操作）。

### 3.6 衔接行 / 其它

- 衔接行随列宽收窄，「补上时长」紧跟文字（760px 下自然靠右，不再跨屏）。
- 顶部信息行（草案/预算/缺照片）保持现状。

## 5. 风险与取舍

1. **DOM 只能有一个父亲**：宽屏时地图要在右栏、窄屏时要在顶部，不能只靠 CSS。方案：地图与目录始终渲染在**同一个右栏容器**里，窄屏时该容器 `order` 到顶部、目录 `display: none`（等价于现状）。这样避免复制组件。
2. 双栏后左侧行程列变窄，长地址会被截断 → 卡片地址已有省略号 + tooltip，可接受。
3. 1080px 断点是猜的：你常用窗口宽度决定它是否合适，可先用 1080 并在实测后调整。
4. 右栏 sticky 与地图自身的拖拽把手、全屏态需要一起验证（全屏态仍覆盖整面板）。

## 6. 验收标准

1. 1332px 宽下：行程列 ≤760px，右栏 sticky——滚动到 D7 时地图仍在原位（截图 + `getBoundingClientRect` 数据）。
2. 380px 宽下：与现在完全一致（地图折叠在顶部、无目录）。
3. 天标题：主行/次行各一行，1332px 下不折行；`1/14` 已从标题移除。
4. 目录：未记录天显示警示点，tooltip 文字正确；强度条比例与 v5.0 相同。
5. `npm run check` 全绿；`.verify` 三档宽度截图。

## 8. 实现记录（0.9.0）

### 8.1 落地方式

- 新增 `.trv-side`：地图与日期目录共用一个「伙伴栏」。
  - `<1080px`：`.trv-side { display: contents }`，地图作为**整宽横幅**排在行程之前（与改动前一致），目录在 560–1080 显示、更窄时隐藏。
  - `≥1080px`（新断点 `SIDE_COLUMN_QUERY`）：`.trv-side` 变成**定高常驻列**（`flex: 1 1 0; min-width: 320px; max-width: 640px`），地图在上、目录在下并自行滚动；行程列 `max-width: 760px`。
  - 采用「定高列」而不是 `position: sticky`：`.trv-body` 是 `overflow: hidden` 的，sticky 在这里不会被行程列的滚动驱动；定高列在同一个 flex 行里天然不动，效果相同且少一层风险。
- 天标题改为两级：主行 `D1 · 09-24 周四  北京 → 西安｜赶路 1,077km`；次行 `行驶 12h38 · 1077 km · 2 站 · 路名`，行尾放动作（交通待重算 / N 提醒）。移除了 `1/14`。
- 目录：未记录的天改为**警示点 + tooltip**，且不再显示与它矛盾的「市内」。

### 8.2 实测（`.verify/trip-layout.mjs`，你那份 14 天行程）

| 面板宽 | `.trv-side` | 行程列宽 | 卡片宽 | 地图高 | 天标题两级 | 滚动时地图位移 |
|---|---|---|---|---|---|---|
| 380px | `contents`（顶部横幅） | 356 | 222 | 170 | 是 | 0 |
| 900px | `contents`（顶部横幅） | 738 | 604 | 242 | 是 | 0 |
| 1332px | **`flex`（右侧常驻列）** | **760** | 626 | 220 | 是 | **0** |

最后一行是这次改版的核心：**滚动行程时地图不再滚走**（改版前地图在首屏横幅里，一滚就消失）。

### 8.3 偏差

- 未使用 `position: sticky`，改用定高伙伴列（理由见 8.1）。
- 深度：`<560px` 完全维持 v5 形态（地图折叠在顶部、无目录），未做任何改动。
