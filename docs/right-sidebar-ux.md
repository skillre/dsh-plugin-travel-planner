# DSH 右侧 Sidebar 体验设计

> 目标：让用户在与 Agent 对话时始终看到当前旅行的空间关系、逐日路线、地点详情和风险。  
> 视觉方向：旅行杂志的精致感 + 公共交通图的清晰信息层级。

## 1. 当前 DSH 契约依据

在 DSH `0.1.5-rc.2`、2026-09-14 的当前运行时中已确认：

- `sidebar.right.pane.tab`：Session 作用域、keyed、无替换风险，用于右栏 tab 正文；
- `sidebar.right.pane.tab.title`：同 key 的动态标题；
- `sidebar.right.tab.menu.item`：向 tab 菜单追加操作；
- Client `layout`：报告右栏普通或全屏呈现；
- 原生包 `@deepseek-ai/dsh-client-ui-sidebar-right` 提供：
  - `ctx.sidebarRightTabs.register(...)`；
  - `ctx.sidebarRight.openTab(...)`；
  - slot 注入的 `useTabInfo` 选择器 hook 提供 tab、pane、navigation、signal 和 actions。

> 实现结论：正文**不要**读这个 hook。它是 `useTabInfo(selector)` 形式的选择器 hook，无参调用会在渲染中抛错；slot 框架会把抛错的登记项标记为 abdicate，整个 pane 就变成空白（实测表现正是「打开后没有任何信息」）。正文只依赖 `sessionId`，布局交给 CSS container query。

实现前仍需重新 Inspect；本文件记录的是设计依据，不是运行时缓存。

建议注册身份：

```text
definition.id   = @skillre/dsh-plugin-travel-planner
definition.kind = skillre-travel
body slot key   = @skillre/dsh-plugin-travel-planner
title slot key  = @skillre/dsh-plugin-travel-planner
```

该类型是 page tab，不声明资源 glob。通过：

```text
ctx.sidebarRight.openTab('skillre-travel', {
  params: { tripId?, dayId?, focusPlaceId?, focusAlertId? }
})
```

打开或聚焦。

## 2. 设计原则

1. **右栏是伴随视图，不是第二个聊天窗口。**
2. **地图和行程使用同一选择状态。** Marker、卡片、时间轴节点共享稳定 ID。
3. **普通模式看重点，全屏模式做编辑。** 不把桌面级功能挤进 360px。
4. **路线段是一等对象。** 地点卡之间必须明确显示如何移动、多久、是否已校验。
5. **风险就地出现。** 告警靠近关联地点或路线，而不是只放在独立列表。
6. **用户决定可锁定。** 已锁定内容拥有明显但克制的状态。
7. **事实带来源。** 高德结果显示来源与查询时间，估算使用不同视觉语义。

## 3. 信息架构

右侧栏只有一个旅行 tab，正文内部采用四个视图：

1. **行程**：默认，逐日时间轴与路线段；
2. **地图**：普通模式中的地图优先视图；
3. **地点**：候选、已采用、排除和锁定地点；
4. **提醒**：错误、警告、待确认与准备度。

使用内部 segmented control 切换，不为每个视图创建 DSH tab，避免污染右栏 tab 条。

## 4. 普通模式布局

目标宽度约 360–480px，由 DSH 布局决定，插件不写死外栏宽度。

```text

│ 10/02–10/04 · ¥5,000          │
├────────────────────────────────┤
│ 行程   地图   地点   提醒 ③   │  内部导航
├────────────────────────────────┤
│ D1 10/02  D2 10/03  D3 10/04 │  横向日期选择
├────────────────────────────────┤
│ ┌────────────────────────────┐ │
│ │ ①──────②                   │ │  轻量地图，约 180–220px
│ │       ╲③                   │ │
│ └────────────────────────────┘ │
│ 步行 2.8km · 46min · 4 地点   │  当日摘要
├────────────────────────────────┤
│ 09:00  ① 西湖断桥       🔒    │
│         景点 · 预计 90min      │
│         │ 步行 12min · 已校验  │
│ 10:42  ② 孤山                 │
│         ⚠ 午餐时间可能偏晚     │
│         │ 公交 24min           │
│ 13:30  ③ 咖啡馆               │
├────────────────────────────────┤
│ 让 Agent 调整        重新校验  │  sticky actions
└────────────────────────────────┘
```

普通模式重点是快速阅读和选择，不在地点卡内展开完整导航步骤。

## 5. 宽窄布局

DSH 右栏已有 fullscreen 呈现，切换时正文不重挂载。插件不读 `sidebar.fullscreen`，而是由**面板自身宽度**决定布局：`.trv-shell` 声明 `container-type: inline-size`，宽于 560px 时正文从单列变为「时间轴 + 示意图/详情」两列。这样既有全屏时的两列呈现，也在用户只是把停靠栏拖宽时同样生效，且不依赖任何运行时 hook。

```text
┌──────────────────────────────────────────────────────────┐
│ 杭州 3 日 · 经典慢游    行程 / 地图 / 地点 / 提醒        │
├──────────────┬──────────────────────────┬────────────────┤
│ Day 列表     │ 地图                     │ Inspector      │
│              │                          │                │
│ D1 西湖      │ ①──②                    │ 西湖断桥       │
│ D2 运河      │    ╲③──④                │ 地址 / 电话    │
│ D3 灵隐      │                          │ 来源 / 查询时间│
│              │                          │ 锁定 / 替换    │
├──────────────┴──────────────────────────┴────────────────┤
│ 逐日可编辑时间轴：地点卡、路线段、冲突、预算             │
└──────────────────────────────────────────────────────────┘
```

全屏模式增加：

- 地图与时间轴同时可见；
- 地点 Inspector；
- 拖动排序；
- 方案比较；
- 详细路线步骤；
- 批量重新校验。

## 6. 组件设计

### 6.1 Trip Header

展示：

- 项目标题；
- 日期和天数；
- 当前方案；
- 状态：草案 / 待处理 / 已就绪；
- 准备度百分比；
- 总预算估算。

准备度不由模型自由填写，应由确定性规则计算，例如：关键路线覆盖率、阻塞告警数、固定预约确认度。

### 6.2 Day Strip

每个日期 chip 展示：

- Day 编号和日期；
- 主区域；
- 告警点；
- 锁定状态；
- 当前选中态。

日期较多时横向滚动，并提供“今天”定位（仅 traveling 状态）。

### 6.3 Route Map

视觉规则：

- 地点 marker 使用与时间轴一致的编号；
- 每天使用一个主题色，但文本和状态不能只靠颜色区分；
- 未选中日期的路线弱化；
- 选中地点时 marker 放大，卡片获得焦点边框；
- 选中路线段时强调对应 polyline；
- 锁定地点 marker 带小锁徽标；
- 告警地点带独立告警环，不覆盖编号。

操作：

- 点击 marker：选中地点并滚动到卡片；
- 点击路线：展开该段摘要；
- “适配当日路线”：恢复地图视野；
- 地图移动不自动修改行程；
- 用户地图点选产生候选地点，必须确认后才写入项目。

### 6.4 Place Card

默认信息：

- 编号、名称、类别；
- 时间和停留时长；
- 简短地址；
- 状态和来源；
- 锁定按钮；
- 更多菜单。

展开信息：

- 完整地址与电话；
- 高德 POI ID；
- 经纬度与 GCJ-02 标记；
- 查询时间；
- 关联提醒；
- 替换、移除、移到其它日期；
- “在对话中讨论”。

### 6.5 Route Connector

地点卡之间显示：

```text
步行 · 1.2 km · 16 min · 已查询 2h 前
```

状态：

- `fresh`：普通强调；
- `stale`：显示重新查询；
- `loading`：保留旧结果并显示进度；
- `failed`：展示原因与重试；
- `missing`：阻塞提醒。

展开后显示 CLI 返回的步骤列表。步骤属于详情，不默认占据窄栏空间。

### 6.6 Alert Card

展示：

- 级别；
- 一句话问题；
- 影响对象；
- 证据；
- 建议动作。

示例：

> **时间冲突**：咖啡馆安排在 13:00，但上一地点加步行预计 13:18 才能到达。  
> 动作：顺延 / 缩短上一站 / 更换附近地点。

### 6.7 Sticky Actions

普通模式底部保留两个主操作：

- **让 Agent 调整**：把当前选择与意图带入对话输入；
- **重新校验**：重新查询过期路线并运行确定性校验。

次要动作放入 DSH tab menu：

- 导出；
- 切换方案；
- 项目设置；
- 清理缓存；
- 关闭当前项目。

## 7. 联动状态

Client 局部状态：

```text
activeView
selectedDayId
selectedPlaceId
selectedLegId
expandedCardId
mapViewport
```

持久业务状态全部来自 Host 的 Trip Project。Client 不把整份 DSH Session、Slot props 或 Service 对象复制进状态。

联动规则：

- `focusPlaceId` 导航参数优先选中地点；
- marker 与 card 双向同步；
- 选择告警时同时选中关联地点或路线；
- Tool 修改完成后按返回的 affected IDs 定位，而不是重置整个视图；
- tab 隐藏或切换 Session 不清空选择；
- tab 的 AbortSignal 结束时释放订阅、地图实例和请求。

## 8. 加载、空状态和错误

### 无项目

展示轻量欢迎页：

- “在对话中描述你的旅行”；
- 最近项目（如果 Host 能提供）；
- 一个示例提示词；
- 不自动创建空项目。

### 加载中

- 保留已有项目，局部显示 route/place skeleton；
- 地图实例初始化与业务数据加载分开处理；
- 不用全屏 spinner 阻塞其它已可用内容。

### CLI 未配置

显示明确动作：

- 缺少 Key；
- 未安装 `amap-gui`；
- 容器未就绪；
- 打开插件设置。

无 CLI 时仍允许查看和手工编辑已有项目。

### 数据过期

保留旧结果并显示“查询于……”和重新验证操作，不突然清空路线。

## 9. 视觉系统

- 继承 DSH 字号、背景、边框和 focus ring；
- 仅组件局部样式，不覆盖全局主题；
- 使用 CSS 变量表达浅色和深色；
- 地图浮层与地点卡共享圆角和阴影层级；
- 动画仅用于 marker/card 选中、视图切换和路线更新；
- 遵循 `prefers-reduced-motion`；
- 目标是清晰、克制、可执行，不使用旅游网站式大面积宣传图。

建议色彩角色：

- Day 1 / 2 / 3：用于路线和编号的小面积区分；
- success：已校验；
- warning：需要注意；
- danger：阻塞；
- muted：候选或过期信息。

## 10. 可访问性

- Marker 必须有与卡片一致的可访问名称；
- 所有功能可用键盘完成；
- tab 顺序遵循 Header → 内部导航 → 日期 → 地图操作 → 时间轴 → sticky actions；
- 地图之外提供等价的地点和路线文本；
- 焦点从 marker 切到卡片时不可丢失；
- 状态不只用颜色表达；
- 图标按钮提供中文和英文 label；
- 触控目标至少 40×40 CSS px。

## 11. 性能边界

- 窄栏只渲染当前日期的完整卡片；
- 地图只绘制当前方案所需 marker 和路线；
- 详细路线步骤按需展开；
- Host 返回项目切片和 revision，不在每次选择时传输整份项目；
- 搜索输入防抖，路线重算显式触发；
- 切换普通 / 全屏不重建地图实例。

## 12. 原型验证清单

在进入原生 Client 实现前，动态原型必须验证：

1. `sidebarRightTabs.register` 类型生命周期；
2. `sidebarRight.openTab('skillre-travel')` 能打开并聚焦页面；
3. 正文与标题都使用 definition id 作为 keyed slot key；
4. navigation params 能聚焦 day/place/alert；
5. 普通与 fullscreen 切换不重挂载正文，且切换后两列布局按面板宽度生效；
6. 切换 Session 后 tab 状态和数据绑定不串线；
7. stop/update 后 Slot、类型、订阅和样式全部移除；
8. 现有 rightbar Guide、Files 和其它 tab 不受影响。
