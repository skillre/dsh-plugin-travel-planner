> **什么时候读它**：当你要决定"一天排几个点、哪几天整天赶路、这个点能不能当锚点、什么时候必须订票、交付前还要查什么"时读这份文件；它不教工具怎么调（那看 SKILL.md / tools.md），只教行程怎么定。

## 标注约定

正文每个数字都带标签，**不要把三类混着说**：

| 标签 | 含义 | 交付时怎么讲 |
|---|---|---|
| **硬线** | 插件代码里的确定行为（校验告警，或重算 / 自动重排的兜底常量），可回源码核对 | 可直接断言 |
| **经验值** | 外部旅行经验数据（来源见文末） | 说"常规经验是…"，**以官方为准** |
| **经验值（推断）** | 本手册在硬线之下收紧的目标值 | **必须标注为估算** |

## 1. 容量模型

### 1.1 插件硬线（先按这些对齐，不要与之对抗）

| 校验 | 阈值 | 口径与后果 |
|---|---|---|
| `DAY_OVERLOADED` | **> 10 h** | 停留 + 交通段 + **转场** > 10h → warning |
| `PACE_EXCEEDED` | **items > 5** 或 **停留+交通段 > 8 h** | **仅当 `pace === 'relaxed'`**；此 8 h **不含转场**（与 10 h 口径不同） |
| `MISSING_ROUTE` | 相邻两项之间无 leg | warning，逐对报 |
| `MISSING_TRANSIT` | leg 同时 < 1000 m 且 < 600 s | 标题写了 `西安 → 成都` 却没记录这段路 → info |
| `ROUTE_STALE` | 交通数据超 **6 h** 未更新 | adaptive：距该天 >7 天不报 / 1–7 天 info / ≤1 天 warning |
| `PLACE_FACT_STALE` | 地点资料超 **24 h** | info |
| `TIME_OVERLAP` | 时间区间相交 | error；**必须 `startAt` 与 `endAt` 同时存在才参与检测** |
| `BUDGET_EXCEEDED` | `estimatedTotal > limit` | warning；只设 `limit` 不设 `estimatedTotal` 只会得到 `BUDGET_UNKNOWN`(info) |
| `readiness` | `1 − 0.25×error − 0.05×warning` | **5 个 warning 才等于 1 个 error**：先把 error 清零，再压 warning |

默认兜底（**只在域层"重算 / 自动重排"里生效；`travel_itinerary_validate` 不使用这些数**）：未写 `plannedDurationMinutes` 且无起止时间 → 按 **45 min** 计；无实测 leg → `直线 × 1.35 × 每公里分钟数`（步行 13 / 公交 3.5 / 骑行 5 / 驾车 2.5）。以上均为 **硬线** 常量——**这是城市速度**（驾车折算约 24 km/h），跨城段靠它会低估 3–4 倍。

> ⚠️ **最大盲区**：`PACE_EXCEEDED` 只对 `relaxed` 计算。`balanced` 与 `intensive` **没有任何站数上限**，插件永远不会告诉你"这天排太多"。用这两档时，**agent 必须自己数 `items.length` 并对照 §1.2**。

### 1.2 三档节奏的排程目标

窗口口径：均衡 / 紧凑按 09:00–21:00（12 h），轻松按 09:30–19:00（9.5 h）。

| 节奏 | 主要停靠 | 顺路点 | items 总数 | 停留+交通目标 | 单日移动 |
|---|---|---|---|---|---|
| relaxed | 2 | 0–2 | **≤5**（硬线） | ≤7 h（硬线 8 h） | ≤1 h |
| balanced | 3 | 1–2 | ≤7（**经验值（推断）**，无硬线） | ≤9.5 h（硬线 10 h） | ≤1.5 h |
| intensive | 4–5 | 2–3 | ≤9（**经验值（推断）**，无硬线） | ≤9.5 h（硬线 10 h） | ≤2 h |

- "主要停靠" = 60–120 min 的核心景点；"顺路点" = 15–45 min 的咖啡馆 / 街巷 / 市集（**经验值（推断）**）。
- 每日 ≤3–4 个主要景点、每天留 1–2 h 无计划（**经验值**）；每项都要显式写 `plannedDurationMinutes`，别依赖 45 min 兜底。
- **体力曲线**：最耗体力的点排 **09:30–11:30**，15:00 后只排顺路点 / 咖啡馆；同行有 60 岁以上或 10 岁以下时，午后必须有 1 个可坐下 ≥40 min 的点（**经验值（推断）**）。

### 1.3 地理聚类（同一天的点必须先聚类，再排顺序）

| 场景 | 判据 | 标签 |
|---|---|---|
| 步行簇 | 簇半径 ≤1.5 km；相邻两站步行 ≤15 min | 经验值（推断） |
| 市内一天的活动范围 | ≤8 km 半径；跨区折返 ≤1 次 | 经验值（推断） |
| 远郊 / day trip | 单程 ≤2 h（外部经验上限为 4–5 h，本手册收紧） | 经验值（推断） |
| 移动占比 | 当天移动时长 ÷ 清醒时间 ≤25% | 经验值（推断） |
| 住宿到首站 | **住宿 → 当天第一个点 ≤30 min**；超了就换住宿区域或换首站 | 经验值（推断） |

原则：**一天一个区**，一天内跨区不超过一次。自查折返：当天点位按顺序连线，出现 **≥2 次方向反转**即折返，重排（**经验值（推断）**）。

### 1.4 时间轴与缓冲

- **每天第一项必须写 `startAt`（硬线级必要条件）**：既没有锁定项、任何项又都没有 `startAt` 时，重算只能改顺序、**改不了时间**。
- 主要活动之间留 30–60 min 缓冲；每连续 2 h 活动补一次 ≥15 min 休息；驾驶每 2 h 停车（**经验值**）。
- 午餐 11:30–13:30、晚餐 17:30–19:30（**经验值**）；午餐给 60–90 min，是半天的天然分界。
- 用餐**写成 item 才计入 8/10 h 硬线**；不写就必须在时间轴上把这段时间留白，否则实际执行会超。
- 每半天至少 1 个"可坐下、可补热水、有卫生间"的停靠（咖啡馆 / 商场 / 游客中心），**按地点 `categories` 挑**（**经验值（推断）**）。

### 1.5 时区与边界日（首日 / 返程日）

- **本行程所有时刻都是"目的地当地时间"**（`TripProject.timezone`，默认 `Asia/Shanghai`）。**出境行程必须在给用户的回复里写明时区**，否则用户会把 09:00 当成本地时间。
- 时差 **≥6 h → 首日不排主要景点**，只留 0–1 个轻量停靠（**经验值（推断）**；CDC 建议时差 >3 h 起就按目的地作息，来源 8）。
- 首日：抵达 → 酒店 → 0–1 个轻量停靠；**抵达 ≥15:00 不排主要景点**（**经验值**）。
- 返程日：**不排需预约项、不排晚餐**；提前 **3 h（机场）/ 1.5 h（高铁站）/ 1 h（市内）** 停止安排；**国际到达**在"落地 → 出关"之间加 **60–90 min 入境缓冲**（**经验值（推断）**，来源 9）。
- 首末日各按 **§1.2 的一半容量**算。

### 1.6 住宿作为锚点

- 把住宿当**当天首站与末站**：用 `travel_route_plan` 实查"酒店 → 首站""末站 → 酒店"两段，把距离 / 时长写进交付摘要（**经验值**，来源 14）。
- ⚠️ **当前行程的里程与时长不含往返住处**——`travel_day_rebuild_legs` 只在相邻 item 之间建 leg，模型里也**没有住宿字段**。交付时必须显式声明，否则用户会低估一天的真实移动。
- **不要把酒店建成 item**（会占站数、抬高 §1.7 强度）；用户坚持写进模型时用 `add-item` + `notes`，并说明它算一个停靠。

### 1.7 每日强度标签（用现有数据算，不新增字段）

先算：`停留` = Σ `plannedDurationMinutes`；`在途` = Σ leg 与 transit 的 `durationSeconds`；`站数` = `items.length`。
判据（需同时满足，**经验值（推断）**）：**低** = 停留 ≤4 h 且 在途 ≤1 h 且 站数 ≤3；**中** = 停留 ≤6 h 且 在途 ≤1.5 h 且 站数 ≤5；**高** = 以上任一超出**且尚未触发 10 h 硬线**。
输出格式：`强度：中（停留 5h10m + 在途 1h20m，4 个停靠）`（**经验值**，来源 16），写进交付摘要与该天标题行。出现"高"就按 §1.2 砍一站再交付；若已触发 `DAY_OVERLOADED`，那不是"高强度"而是"要改行程"。

## 2. 编排顺序（从用户一句话到逐日行程）

严格按序，不要跳步：

1. **收约束**（§3）→ `travel_project_create`。没有出发日期与目的地时不要开工。
2. **定锚点**：锚点 = 必去项 + 固定预约 + 抵达 / 离开时刻。先变成 items，再 `set-item-lock` + `set-item-time` 写死起止（锁定项在重算时是锚点，后面的项去适配它，而不是把它挤走）。**放票日可能晚于行程日的点不能当锚点**，见 §3.3。
3. **搜地点**：`travel_place_search`；只把真要用的点入库，其余留 candidate。
4. **聚类分区**：读坐标按 §1.3 分簇，一天一个区；再把锚点分配到具体日期（受固定时刻、闭馆日、放票窗口约束），然后往里填顺路点。
5. **排时间**：先写当天第一项 `startAt`，再逐项 `set-item-time`（`startAt` + `endAt` + `plannedDurationMinutes`），按 §1.2 控总量。
6. **补交通**：每天 `travel_day_rebuild_legs`（返回 `{dayId, legs, totalDistanceMeters, totalDurationSeconds, skipped[]}`）；**改序 / 增删点后必须重刷**。要检查 **`skipped[]`**——它是"无法规划的点对"清单（通常是地点缺坐标），逐对补全后重刷。
   **一天只吃一个 `mode`（硬线），真实城市行程是混合的**：先按当天主方式（`transit` / `driving`）刷一遍，再对**短段（<1.5 km）**单独 `travel_route_plan(mode:'walking')` + `set-leg` 覆盖，长段保留公交 / 驾车。
   *某段是不是真实数据，看 `travel_project_read` 里该 leg 的 `freshness` 与 `source`，以及校验给出的 `MISSING_ROUTE`。**不要去找 `estimatedPairs` / `staleLegIds`：它们只存在于域层重算结果里，不进任何模型可见的返回体。***
7. **算预算**：写 `set-budget` 的 `estimatedTotal`；在对话里给 5 项分解（住宿 / 餐饮 / 门票 / 市内交通 / 城际），**相加必须等于 `estimatedTotal`**。
8. **校验**：`travel_itinerary_validate`；error 清零后再压 warning；过 §6 的 8 问；`readiness` 未达预期不要宣称"就绪"。
9. **交付**：`travel_project_export` + §4.3 的待确认清单 + §4.3-5 的备选清单。

## 3. 约束收集清单

### 3.1 动手前必须问（每条都写清不问的代价）

| 项目 | 不问会怎么坏 |
|---|---|
| 出发 / 返回日期与**确切时刻** | 首末日按整天排，必然执行不了；`set-trip-dates` 后全部重排 |
| 出发地与目的地城市，**目的地时区**（若与默认不同） | 出境行程日期与时刻全错还不自知，见 §1.5 |
| 同行人构成——**问三问**：① 有没有人不能连续走 30 min 以上？② 需要轮椅、助行器或婴儿车吗？③ 需要午睡吗？（再补证件类型，决定实名与儿童票口径） | 节奏与步行量全错；实名 / 儿童票口径错，现场进不去。**这三个答案直接决定停靠数与午后时段**——比"有没有老人小孩"这种形容词可判定得多 |
| 必去清单，及**是否预约制、放票时间、有无当日票**；是否撞节假日 / 长假 | 放票晚于行程日的点根本排不进去（§3.3），返工成本最高；长假还会改变人流与放票窗口 |
| 城际交通方式（自驾 / 高铁 / 飞机） | 跨城日的结构与时长完全不同 |
| 住宿地点或区域 | 每天起点与首末站全错，路线整体失真 |
| 预算上限，及**是否含机票 / 住宿**、几人几间几晚 | 预算告警永远对不上口径 |
| 已有预约（时刻 + 是否可改 + 凭证号） | 与锚点冲突时无从取舍；凭证号过期就补不进 notes |
| 自驾时：车停哪、酒店有无车位 | 只问不查，答案写进当晚住宿的 notes；**不写"停车费 20 元"这类数字** |

### 3.2 可合理默认（但要在交付时声明）

| 项目 | 默认 | 说明 |
|---|---|---|
| 节奏 | `balanced` | 用户说"慢 / 不赶"改 `relaxed`（顺带启用站数保护） |
| 每天开始时间 / 单项停留 | 09:00 / 45 min | 每天第一项**必须写 `startAt`**，否则无法自动重算；停留 45 min 仅兜底 |
| 市内移动方式 | `transit` | 用户偏好优先；短段再按 §2-6 覆盖为 walking |
| 入住 / 退房 | 15:00 / 11:00 | **只有用户明确提供才改**，别当事实写进 notes |
| 货币 / 时区 | CNY / Asia/Shanghai | 插件默认；出境行程必须问清时区 |
| 顺路点 | agent 在锚点间顺路补 | 用户通常不指定，但不得超过 §1.2 上限 |

### 3.3 预约与放票窗口（中国境内最强现实约束）

- 必去且需预约的点，**必须问**："放票时间是什么时候？有没有当日票？"
- **判据（决定该点能不能当锚点）**：**放票时间晚于行程中要用它的那一天 ⇒ 该点不能当锚点**。改排备选点，把放票窗口写进该点 `notes`（只能在 `add-item` 时写），并列进待确认清单。
- 提前量经验值（**全部为 经验值，务必以官方放票窗口为准**，来源 3）：国内机票 ~30 天、国际机票 ~45 天、跨城高铁 ~15 天、限流景点 ~7 天、网红餐厅 ~3 天、旺季酒店 ~30 天。
- **交付时按出发日倒推成三档**（**经验值（推断）**）：`立即订` / `出发前 1–3 个月` / `出发前 2–4 周`。
- 证件与实名：只问"谁去、用什么证件"，写进 notes 与同行人标签对照；**不查政策、不给结论**（来源 1）。

## 4. 工具能力边界

### 4.1 插件**没有**的数据（禁止编造）

`TripPlace` 只有：名称、地址、坐标(GCJ-02)、电话、图片、类别、来源。**没有营业时间、没有评分、没有实时票价、没有天气、没有班次与放票。** 营业时间、闭馆日、最后入场、评分、排队时长、门票价格、预约与放票窗口、班次时刻、天气、实时拥堵——这些只可能来自模型记忆或用户输入，**必须标注"未核实"**。

### 4.2 可写字段的真实边界（23 个 patch op 实测）

| 想表达 | 能否写入 | 正确落点 |
|---|---|---|
| 必去 | ✅ | 加入 items + `set-item-lock` true |
| 固定预约（时刻） | ✅ | item 的 `startAt`/`endAt` + `set-item-lock` true（重算时作锚点） |
| 避开某类地点 / 兴趣标签 / 无步行时长要求 | ⚠️ **写了但不生效** | `set-preferences` 的 `avoid`、`interests`、`maximumWalkingMinutesPerLeg` **能写进文档，但插件全库没有任何读取方**：不告警、不重排、不影响搜索。所以只能说**"我已按这个设计"**，**不能说"插件会按它约束 / 校验"**——那是会出事故的错误承诺。执行者永远是 agent 自己的排程判断 |
| 营业时间 / 闭馆日 / 预约窗口 / 预约号 / 订单号 / 地址电话 | ⚠️ 半 | item 的 `notes`，**但只在 `add-item` 时可写** |
| 待确认事项 | ⚠️ 半 | 同上，或导出文档的"待确认"清单 |
| **方案分支（雨天版等）** | ❌ | **没有任何 op 能新建 scenario**；`scenarios` 只有 `main`，见 §4.3-5 |
| `constraints[]` | ❌ | **没有任何 op 能写**（项目创建时固定为 `[]`）。**不要承诺"已写进约束"** |
| 预算分类明细 | ❌ | 模型只有 limit / estimatedTotal / confirmedTotal 三个数，分解只能写文档 |

> **三个必须记住的硬事实**：① **"必去 / 固定"只能靠 `set-item-lock` + `set-item-time` 表达**——`constraints[]` 写不进去，lock 是唯一机器可判定的"不许动"。② **`item.notes` 只在 `add-item` 时能写**，没有更新 op；事后补只能**删掉重建**，而重建会丢 item id 与其 leg，必须重跑该天 `rebuild_legs` → 地址、电话、预约号、放票窗口、雨天替代**建档时一次写全**。③ **方案分支不可用**（见下条）。

> **偏好里只有两个字段会真的改变插件行为**：`pace`（只有 `relaxed` 触发 `PACE_EXCEEDED`：items>5 或 停留+交通段>8 h，`src/domain/validation.ts:588`）与 `preferredModes[0]`（决定 `rebuild_legs` / `set-transit` 的缺省出行方式，`src/host/travel-service.ts:642,737,1055`）。其余偏好字段只作留档。**"同行人不能久走""需要无障碍"这类要求，插件永远不会替你把关**——写进 notes 前缀，并在交付时说明这是你排的、不是插件校验过的。

> **op 顺序坑**：当天只要有一个锁定项，`set-day-title` 与 `remove-day` 就会被拒（`ITEM_LOCKED`）。所以想写"D3 工作日｜会场"这种标题**必须先写标题再上锁**。

### 4.3 把"不可知"转成"可判定"

1. **营业时间 → 排序规则**：不编造"9:00–17:00"，改成"这一天只排在上午"，把结论写进 item `notes`，并把不确定明说出口。
2. **闭馆日 → 天的分配**：**主动问**"你必去的那几个馆，知道周几闭馆吗？"；答不上就默认把该区排到**周二 / 周三**，并把"闭馆日未核实"写进待确认清单。
3. **必须保留 → lock**：用户说"这个必须去"就用 `set-item-lock` true。
4. **不确定项 → 统一占位符**：正文凡涉及营业时间 / 票价 / 预约窗口的排程句，必须带 **`⚠ 待确认：<事项>（需你确认 / 到场确认）`** 或 **`—`（未知数值）**，而不是只在末尾列清单——用户要能分清哪一行是查过的。
5. **雨天 → 文档级备选清单 + 室内锚点（⚠️ 方案分支不可用）**：`scenarios` **只有 `main` 一个**，`set-active-scenario` 只能切换到**已存在**的方案，**没有任何 op 能新建方案**（`src/domain/patch.ts:418-421`、`patch-ops.md:44`）。落地成三件事：① 每天至少 1 个"室内锚点"（晴天也值得去的馆 / 商场 / 咖啡馆），能在 30 min 内切换；② 建档时就在 `notes` 里用固定前缀 **`[雨天替代→dX]`** 标出它替代哪天哪一站（`[锚点]` / `[可跳过]` 同法；**前缀只是给人看的，机器语义只有 `locked`**）；③ 在**导出文档**末尾追加"备选清单：若 D2 下雨，用 X 替换 Y"。
6. **封闭 / 降级时的取舍**：先确定"最坏情况下**唯一必保项**"，用 `set-item-lock` 锚定它，其余全部保持可移动——这样任何临时调整都不需要重排整趟。

## 5. 跨城赶路日

| 判据 | 数字 | 标签 |
|---|---|---|
| 舒适驾驶日 | 4–6 h 方向盘时间，300–500 km | 经验值 |
| 绝对上限 | 8 h，且**不可连续两天**；带儿童降到 4 h | 经验值 |
| 同行有 60 岁以上 | 连续乘车 ≤2 h、连续游览 ≤3 h；过夜或连续乘车 >8 h 应安排卧铺、宜下铺 | 行业标准 LB/T 052-2016 **[二手]** |
| 风景线减速 | 地图时间 ×1.5（观光）/ ×2（山海盘山） | 经验值 |
| 何时不排主要景点 | 单程纯交通 ≥4 h | 经验值（推断） |
| 何时整天只赶路、零站点 | 单程 ≥6 h 或 ≥500 km | 经验值（推断） |
| 多城节奏 | 净天数 ÷ 目的地数 ≥ 3 | 经验值 |

**跨城日标准结构**（**经验值（推断）**）：市内到站 40 min + 候车 30 min + 车程 + 出站 30 min + 到酒店 40 min。落地要求：**把"出站 / 到酒店"变成真实 leg**——两端都入库为地点，跑 `travel_route_plan` 后 `set-leg`，别停在经验值上。
**至少给两种方式的真实对比**：跨城段用 `travel_route_plan` 换 `mode` 各跑一次（驾车 vs 公交 / 骑行，可行时），把两组里程与时长都讲给用户再落最终 leg。**公交必须带 `city`（硬线）**，跨城公交不能伪装成本地公交结果。

**必须用 `travel_day_set_transit` 而不是 leg**：
- 转场记录的是"移动"本身，**不计站数、不计停留**，只计里程与行车时长——只有转场没有站点的日子是完整的一天。
- 只在标题写 `西安 → 成都｜723km` 而没记录 → `MISSING_TRANSIT`（硬线）；最长一段 ≥100 km 且占当天移动 ≥80% → 告警措辞自动切为"单日驾驶偏长"，建议"中途加一晚住宿"（**硬线**）。

## 6. 交付前 8 问（主动逐条自查，全过才说"就绪"）

| # | 自查项 | 不过怎么办 |
|---|---|---|
| 1 | 跨城段扎堆了吗？两个 ≥6 h 的长途日是否相邻？ | 中间加一晚住宿，或拆成两天 |
| 2 | 每天 `items.length` 是否在 §1.2 上限内？（balanced / intensive **无硬线**，插件不会提醒） | 超了自己砍，别等告警 |
| 3 | 每对相邻 item 都有 leg 吗？`rebuild_legs` 的 `skipped[]` 是空吗？ | 逐对 `travel_route_plan` → `set-leg` |
| 4 | 时间是否 `startAt`/`endAt` **成对**写？每天第一项有 `startAt` 吗？ | 补齐，否则重叠不报、拖拽不改时间 |
| 5 | 首末日按半天算了吗？返程日有没有排需预约项或晚餐？国际到达加 60–90 min 了吗？ | 按 §1.5 改 |
| 6 | `estimatedTotal` 填了吗？5 项分解相加等于它吗？人数口径对吗（门票 / 餐饮 / 城际乘人，住宿按间）？ | 改到相等再交付 |
| 7 | "必去 / 固定"是否用 `set-item-lock` + `set-item-time` 表达？（`constraints[]` 写不进去） | 补 lock |
| 8 | 待确认清单列了吗？正文排程句带 `⚠ 待确认：…` 或 `—` 了吗？备选清单写进导出文档了吗？ | 补上；方案分支不可用，别承诺 |

## 7. 失败模式清单

| # | 症状 | 原因 | 修法 |
|---|---|---|---|
| 1 | 赶路日被报"空日"或"超 10 小时" | 只有标题写了 `A → B` 而没记录；或把转场当成了过载 | 用 `travel_day_set_transit` 升级为真数据，告警措辞会自动切换 |
| 2 | 连续两天 8 h 驾驶 | 长转场排相邻 | 中间加一晚住宿，或拆成两天（绝不连续两个 8 h 日） |
| 3 | 每城只住 1 晚，天天收行李 | 违反多城节奏 | 净天数 ÷ 目的地数 ≥ 3；不达标就砍掉一个目的地 |
| 4 | 预算设了上限却从不报警 | `estimatedTotal` 没填，而 `BUDGET_EXCEEDED` 依赖它 | 必须写 `set-budget` 的 `estimatedTotal` |
| 5 | 到现场发现闭馆 | 插件无营业时间数据 | 主动问闭馆日；答不上就把该区排到周二 / 周三并列入待确认 |
| 6 | 几个月后的行程报一堆路线过期 | 6 h 过期阈值 + adaptive 分级 | 出发前 7 天内统一重刷一次；7 天外不必刷 |
| 7 | 同一天城东→城西→城东 | 没做地理聚类 | 按 §1.3 聚类，一天一区，用折返判据自查 |
| 8 | 想给某站补备注，结果连接丢了 | `notes` 只在 `add-item` 时可写 | 一开始写全；要补就删掉重建并重跑该天 `rebuild_legs` |
| 9 | 把"门票约 60 元"说成事实 | 插件不提供票价，模型凭记忆补 | 一律标注"估算，未核实"，写进待确认清单 |
| 10 | 承诺了"雨天版方案"，现场切不过去 | `scenarios` 只有 `main`，没有创建方案的 op | 改为文档级备选清单 + notes 前缀 `[雨天替代→dX]`，见 §4.3-5 |
| 11 | 出境行程时刻全错 | 插件默认 `Asia/Shanghai`，未声明目的地时区 | 声明"所有时刻为目的地当地时间"，并在回复里写明时区 |
| 12 | 一天内该走路的段被算成公交 | `rebuild_legs` 一天只吃一个 `mode` | 短段（<1.5 km）用 `travel_route_plan(mode:'walking')` + `set-leg` 覆盖 |
| 13 | 用户按行程单算出的一天比实际短 | 里程 / 时长不含"住处↔首末站" | 交付时显式声明，并实查这两段写进摘要 |
| 14 | 交付后才发现票早已放完 | 没问放票窗口，把预约制点当成了锚点 | 按 §3.3 问窗口；放票晚于行程日的点改排备选 |
