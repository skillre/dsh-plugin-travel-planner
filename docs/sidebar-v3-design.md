承接 `docs/sidebar-v2-design.md`。本文针对 0.2.0 实际使用后提出的六个问题给出方案。
观测版本 DSH `0.1.6-alpha.1`；结论一律以真实截图与本机实测为准。

## 0. 摘要

| 你提的问题 | 方案 | 代价 / 风险 |
|---|---|---|
| 地图标记不明显 | 重做标记：水滴 pin + 编号/起终徽标 + 白描边 + 投影，选中放大并加光晕；补图例条 | 纯前端，无风险 |

| 告警是什么、为什么这么多 | 每条告警给「含义 / 原因 / 一键消除」；**把路线过期按出发远近降级并按天聚合**；就绪度只计可行动告警 | 改变评分口径，需在 README 同步说明 |
| `30%` 是什么 | 环上写「就绪度」并加 `ⓘ`，点开列出明细公式 | 无 |
| 想看整个行程的全部路线 | 地图加「当天 / 全程」范围切换；全程按天着色 + 图例 + 聚焦 | 天数多时色板不足，>5 天改为「当天彩色 + 其余灰度」 |
| 排序要点开详情按按钮 | 时间轴**直接拖拽**排序；拖完**自动重排当天时间**，再可一键交给 Agent 用真实路网复核 | 拖拽在窄栏有误触风险，用把手 + 阈值 + 键盘替代 |
| 页面太朴素 | 采集 POI 真实照片 + 类别色带 + 章节式日期头（方向 A+C） | 外链图片需容错；域名策略见 §5.4 |

## 1. 地图可读性与尺寸

### 1.1 现状问题

截图里 1–5 号点是 22px 白底圆 + 1px 浅描边，铺在色彩密集的高德底图上几乎融进背景；
且卡片固定 `height: 168px`，没有任何放大入口。

### 1.2 标记重做

```text
      ┌────┐          · 高约 30px，编号 12px/700
      │ 3  │          · 底 brand-primary，文字 #fff
      └─┬──┘          · 2px 白色描边 + 0 2px 6px rgba(0,0,0,.35)
        ▼             底部尖角，anchor 指向真实坐标（anchor:'bottom-center'）

  起点/终点不用数字，用文字徽标： ╭──╮  ╭──╮
                                   │起│  │终│
                                   ╰──╯  ╰──╯
```

- 颜色：起点 `--dsw-alias-state-success-primary`，终点 `--dsw-alias-state-warn-primary`，中间站 `--dsw-alias-brand-primary`；**同一天内不同站不再换色**，避免与「按天着色」冲突。
- 选中：缩放 1.25 + 外圈 2px 光晕 + 呼吸动画（`prefers-reduced-motion` 下关闭）；同时地图 `setCenter` 把它移到视口内。
- 层级：选中 > hover > 其余；重叠时按天内顺序抬升，保证小编号盖住大编号不被遮。
- 地图右下角加**图例条**（可折叠）：`①…⑤ 当天顺序 · 起 · 终 · 虚线=顺序（非路网）`。
- 实现：继续用 AMap `Marker` 的 `content` DOM 节点，样式走 CSS（含主题 token），点击绑定不变。

### 1.3 尺寸：三档 + 可拖

| 档位 | 高度 | 用途 |
|---|---|---|
| 紧凑 | 168px | 默认，看顺序就够 |
| 舒适 | 260px | 看清道路与地名 |
| 全屏 | 面板剩余全部高度 | 认真看路线 |

- 卡片右上角一个按钮循环三档（图标随之变化：`⤢` / `⤡`），另在卡片底边提供**拖拽调高**（pointer 拖动，范围 120px → 面板 70%），拖动结束吸附到最近档位。
- 全屏态：地图铺满面板，时间轴变成**底部抽屉**（默认收起，露出当天前 2 站，可上滑展开），顶部保留行程切换器与日期翻页器；`Esc` 退回。
- 选择记忆在 `localStorage['skillre-travel:ui']`（本地 UI 偏好，不写进项目文档，避免污染可版本控制的 `trip.json`）。
- 宽栏（≥560px）时地图独立成列，高度跟随列高（sticky），三档按钮仍可用。

## 2. 信息可解释性

### 2.1 就绪度 30%

- 环里写数字、环下方加 10px 标签「就绪度」。
- 点击展开说明卡：

```text
就绪度 30%
─────────────────────────────
口径：1 − 0.25 × 阻塞数 − 0.05 × 警告数（最低 0）
你当前：0 条阻塞、14 条警告 → 30%

它衡量的是「这份行程还有多少不确定项」，
不是行程好坏；把下面 14 条清掉就会回到 100%。
[ 查看这 14 条 ]  [ 一键全部刷新 ]
```

### 2.2 告警到底是什么——顺带修一个产品缺陷

**现在的 14 条警告里 13 条是「路线超过 6 小时未更新」。** 这不是显示问题，是规则口径问题：
任何一次查询过的路线，6 小时后自动过期；一份隔了两周才出发的行程，光靠时间流逝就能把就绪度压到很低，
而这 14 条**没有任何一条需要用户当下行动**。方案：

1. **按出发远近分级**（新增配置 `alerts.routeStaleMode: 'adaptive' | 'strict'`，默认 `adaptive`）：

| 距该天出发 | ROUTE_STALE 严重度 | 理由 |
|---|---|---|
| > 7 天 | 不产生 | 现在重算也会在出行前再次过期 |
| 1–7 天 | info | 只需知道 |
| ≤ 24 小时 | warning | 该重算了 |
| 已经过期且行程进行中 | warning | 影响当下 |

2. **按天聚合**：同一天的多条过期合并为 1 条：
   「D1 有 4 段交通超过 6 小时未更新」→ 细节列在展开区。14 条 → 3 条。
3. **就绪度只计可行动告警**：`info` 不计入；这样「没做事」不会掉分，「有阻塞」才掉分。
4. **每条告警可行动**：
   - 中文类别名 + 图标（缺交通 / 路线过期 / 时间冲突 / 单日过载 / 地点未知 / 预算超限 / 事实过期 / 节奏超限）
   - 三行结构：**是什么**（一句话） · **为什么**（具体到哪两站） · **怎么消**（按钮）
   - 动作：`重算这一天交通`（新接口，见 §6）、`定位到那一段`（跳转并高亮）、`忽略本次`（写入 `state.json.alerts.ignored`）
5. 头部的 `14 警告` 徽标：改成可点击（直接打开提醒面板），首次出现时旁边浮一个 `ⓘ` 气泡解释一次。

### 2.3 `⋯` 菜单

| 图标 | 标题 | 副标题 |
|---|---|---|
| 🗂 | 地点库 | 候选与已采用的地点，可切换状态 |
| ⚠ | 提醒与冲突 | 校验发现的问题，可一键修复 |
| 🧭 | 在地图中打开当天 | 打开桌面高德窗口，看精确路网与街景 |
| ↻ | 重新读取 | 立即刷新面板数据 |

## 3. 全程路线图

地图卡顶部加**范围切换**：`当天 | 全程`（记住选择）。

```text
全程模式
┌──────────────────────────────────────────┐
│ [当天] [全程]                    ⤢     │
│                                          │
│   D1 蓝 ────·──·        ▣ D2 绿          │
│        ·───·   D3 橙 ────·──·            │
│                                          │
│ 图例  ●D1 9/25 ●D2 9/26 ●D3 9/27        │
│       （点图例聚焦某天，其余降到 30%）    │
└──────────────────────────────────────────┘
```

- 每天一条折线，颜色按天索引取主题色序列（`brand-primary`、`state-success`、`state-warn`、`state-error` + 两个派生色）；>5 天时切「当前天彩色、其余灰度」。
- 编号仍按天内序号，颜色跟随当天；起点/终点徽标只在当天显示。
- `fitView` 到全部点；跨度超过约 200km（跨城）时提示「已切换到全程视角，放大查看某天」。
- 与时间轴联动：切换天时地图保持全程并**只高亮当天**；宽栏滚动时间轴时按天高亮（scroll-spy）。
- 数据来源不变：`view.days[*].items[*].point`，前端聚合成 `Map<dayId, path>`；不新增 host 接口。

## 4. 拖拽排序与时间自适应

### 4.1 交互

- 每行左侧一个拖拽把手（`⠿`，仅把手可拖，避免整行误触）；指针按下 6px 后才进入拖拽，行抬升（阴影 + 1.02 缩放），其余行让位（120ms 过渡），落点显示 2px brand 指示线。
- 靠近容器上下边缘自动滚动；**跨天拖动 v3.1 再做**（先把天内做扎实）。
- 键盘替代：选中行后 `⌥↑/⌥↓` 移动，`aria-live` 播报「天安门广场 移到第 2 位」。
- 乐观更新：拖动结束立刻改本地顺序，再发 `POST /patch`；失败回滚 + 顶部提示。
- **详情抽屉去掉「上移/下移」**，保留 锁定/解锁、移除、在地图中定位；锁定改为行内小锁图标点击切换。

### 4.2 时间自适应（两层，都是真的）

**第一层：确定性重排（Host，立即，无需模型）**

新增 `POST <prefix>/reflow-day`，纯函数实现放在 `src/domain/reflow.ts`：

```text
输入：dayId、可选的新顺序 order[]、锚点（当天第一项的 startAt，或锁定项时间）
规则：
  1. 以第一个「锁定项」或当天起始时间作为锚点
  2. 依次累加：本项停留时长 + 到下一项的实际交通时长
     停留时长 = plannedDurationMinutes ?? (endAt − startAt) ?? 45 分钟
     交通时长 = 已存 leg.durationSeconds ?? 同模式中位数 ?? 按模式估算
  3. 锁定项时间保持不动，作为下一段的锚点
  4. 重排后所有被影响的 leg 标记 freshness='stale'（现有字段）
  5. 若推算结果与锁定项冲突 → 保留锁定项并产生一条 TIME_OVERLAP 告警
输出：新的 items 时间 + legs 的 stale 标记 + 一份「受影响项」清单
```

时间轴顶部随后出现一条操作条：

```text
已按停留时长重排 · 交通时长为估算值      [让 Agent 用真实路网重算] [确认]
```

**第二层：Agent 复核（可选，一键）**

`让 Agent 用真实路网重算` 通过 slot 标准 prop `inputActions` 把准备好的指令交给输入框：

```ts
inputActions.setDraft(
  'D1 的顺序改成了：天安门广场 → 景山公园 → 故宫博物院（午门） → …\n' +
  '请用 travel_day_rebuild_legs 重新计算相邻两站的真实交通，' +
  '并据此校正当天各站时间；已锁定的安排保持不动。'
)
```

默认只**写入草稿**不自动发送（用户可改可删，按回车才发）；设置里可开「直接发送」。
这条路径用的是真实契约：`InputActions.setDraft(text)` / `submit()`（`dsh-client-ui-conversation` 的 `contract/input.d.ts`），
不是自造的假 AI。

### 4.3 为什么不让前端直接"AI 处理"

前端不认识模型，也不能保证结果可信；而 Agent 手上有 `travel_day_rebuild_legs`（真实高德路网）、
`travel_itinerary_validate`（确定性校验）和工具链。所以：**确定性的部分留在代码里立即生效，判断性的部分交给 Agent**，
两者用一条可编辑的指令串起来。

## 5. 视觉升级

### 5.1 核心杠杆：把 POI 的真实照片用上

高德 CLI 的 POI 响应里本来就有 `photo` 字段（`store.is.autonavi.com/...`），我们目前**没有采集**。
采集它（`AmapPoi.photoUrl` → `TripPlace.photoUrl`），时间轴每一站与详情抽屉就能显示真实缩略图。
这是「好看」最有效的一步：真实照片 > 任何 CSS 技巧。

- 容错：加载失败/无图时回退到类别图标占位（不出现破图）。
- 尺寸：列表 44×44 圆角 10；详情抽屉顶部 16:9 横幅（无图则不占位）。
- **实测（2026-09-15）**：两个 POI 图片地址直接 `curl` 均返回 200 与真实 JPEG 字节（54KB / 143KB），
  没有防盗链，可以直接 `<img>` 引用。
- 注意：这些是 `http://` 地址。当前 DSH 页面在 `http://127.0.0.1:3080`，不构成混合内容；
  若将来通过 https 反代访问，浏览器会拦截，届时需要改为经 Host 代理图片（或关掉 `ui.placePhotos`）。

### 5.2 三个方向

**方向 A｜行程册（卡片化 + 类别色带）**
- 每站一张卡：左侧 3px 类别色带（风景/餐饮/交通/住宿/购物），44px 缩略图，右上角时间（16px 等宽），卡内 2 行元信息。
- 日期头做成章节条：左侧大号 `D1`，右侧日期与总时长，底部一条进度点（D1●●○）。
- 地图卡：内描边 + 顶部 12px 渐隐遮罩（让图例更清楚）。
- 信息密度高、扫读快，适合执行中查行程。

**方向 B｜地图优先（沉浸式）**
- 地图占面板上半到全部，时间轴以半透明浮层（`bg-overlay` + `backdrop-filter: blur(12px)`）浮在其上，滚动时背景地图跟着平移。
- 视觉冲击最强，但文字信息少，适合路线审视。

**方向 C｜旅行杂志**
- 大标题 + 日期章节封面（用该天第一站的照片做封面图）+ 多留白 + 图片墙的地点库。
- 出行前慢慢读最舒服，执行中信息密度偏低。

### 5.3 推荐：A 为主，吸收 C 的日期章节

组合理由：这是个**执行工具**，信息密度优先；但把日期头做成章节样式、站点带缩略图、地点库做成图片墙，
就能同时拿到「好看」和「好用」。具体清单：

1. 站点卡：缩略图 + 类别色带 + 大号等宽时间 + 停留时长徽标
2. 日期章节头：`D1` 大字 + 日期/星期 + 当天总时长与距离 + 进度点
3. 地图：任务 A 完成后的 pin + 图例 + 范围切换
4. 动效：拖拽抬升、选中呼吸、地图 pin 弹入（150ms）、`prefers-reduced-motion` 全关
5. 空/错状态：插画式占位（SVG）+ 一句行动建议
6. 地点库：两列图片墙（有图大卡、无图紧凑行）

### 5.4 新引入的边界

- **外链图片**：DSH 页面当前无 CSP，允许 `<img>` 外链；图片来自高德 CDN，属第三方可见你的 IP（与地图瓦片同源风险）。提供开关 `ui.placePhotos: 'auto' | 'off'`（默认 `auto`），关掉即用图标占位。
- `trip.json` 增加 `photoUrl` 字段：老文档缺字段时前端跳过，不需要 schema 迁移。

落地时的偏差，均已记录在 `.changeset/` 与对应提交说明里：

- `POST /reflow-day` 同时承担「只重排时间」与「重排 + 改顺序」，避免两个近义接口。
- 重排后的交通：**已测过的配对保留数值并标 `stale`，没测过的配对不编造 leg**，
  让 `MISSING_ROUTE` 如实出现；面板提供「重算这一天交通」（走 CLI，不花 token）与
  「让 Agent 复核」两条路径。
- 锁定项**允许被拖动位置**——它保持自己的时刻并成为后续项的锚点；
  由此产生的时间冲突照常以 `TIME_OVERLAP` 暴露，而不是悄悄挪走用户钉住的时间。
