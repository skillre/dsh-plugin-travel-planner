> **什么时候读它**：当你要决定"这一天该长什么样、时间不够先砍谁、同一堆点怎么排序、必去撞车怎么取舍、临时变卦怎么补位"时读这份文件。它是**设计层**手册：容量阈值、地理聚类、约束收集、放票窗口、交付前 8 问、失败模式在 `itinerary-craft.md`，本文件只写增量、只做指针。

**数字标签**：`硬线`（可在插件源码核对）｜`经验值`（有外部出处，见文末「来源」）｜`经验值（推断）`（在出处之下收紧的估算，交付时必须讲成估算）｜`权威出处`（法规 / 民航局 / CDC 类，正文点名）。只有媒体转述的数字标 **[二手]**。
**标记口径**：`[锚点]` `[可跳过]` `[闭店备选→dX]` `[雨天替代→dX]` `[并行]` `[缺席]` 都是**写给你和用户看的字符串**；机器语义只有 `locked` 一个（`src/domain/patch.ts:651,682,748`）。
**能力边界（全文适用）**：**查得到** POI 名称 / 地址 / 坐标 / 电话 / 照片 / 类别、四种出行方式的距离时长、驾车途经点、跨城真实路径；**查不到** 营业时间、闭馆日、评分、排队、票价、天气、人流。**写得进** `pace`/`interests`/`avoid`/`preferredModes`、item 的 `startAt,endAt,plannedDurationMinutes,locked,notes`、地点 `status`、交通段、转场、预算三个数；**写不进** `constraints[]`、无障碍字段、票价字段。

## 1 日型模板：抵达日 / 完整日 / 移动日 / 返程日 / 休息日

先选日型。三问任一为"是"就按**半日型**排容量（**经验值（推断）**）：① 那天有固定时刻的移动吗？② 行李在身上吗？③ 可用窗口 <6h 吗？

| 日型 | 起床 | 主要锚点 | 留白 | 晚餐 | 什么时候用 |
|---|---|---|---|---|---|
| 抵达日 | 不设，按落地时刻 | 0 个（落地晚时）/ 1 个轻量 | 整段傍晚 | 不排固定位 | 第一天，或当天有长途到达 |
| 完整日 | 08:00–09:00 | 1 主 + 1 次 | ≥90min | 可排 1 个可订位 | 净整天、没有固定移动 |
| 移动日 | 按车次 | ≤2（行李已安置）否则 ≤1 | 不适用 | 不排固定位 | 换城市 / 换住宿那天 |
| 返程日 | 按起飞时刻反推 | 0 个（起飞 <18:00） | 不适用 | 不排 | 最后一天 |
| 休息日 | 不设闹钟 | 0 个（最多 2 个顺路点） | 半天以上 | 可排，且是当天唯一固定项 | 行程 ≥5 天，按下面频率插 |

（整表为 **经验值**；抵达时刻阈值与首末日容量减半沿用 itinerary-craft §1.5，此处不重复）

- **抵达日的傍晚块必须同时满足三条**（**经验值（推断）**）：① 从住处出发 ≤20min（查一次 `travel_route_plan`）② 免票、免预约 ③ `startAt` 在当地 17:00 后。
- **长途到达的次日**：时差 ≥6h 或飞行 ≥8h → 起床后第一个活动的 `startAt` 不早于 10:00（**经验值（推断）**）。
- **移动日**：锚点 ≤2，且只有"行李已安置"（已寄存 / 随车 / 已送达）时成立，否则 ≤1（**经验值**）。行李在手上那天不排需要存包的点。
- **返程日**：起飞 <18:00 → 主要景点 0 个，只留"住处 → 车站/机场"一段加一顿非正餐（**经验值（推断）**）；需预约项与晚餐一律不排（见 itinerary-craft §1.5）。
- **休息日是零义务日**，不是"只排两个点的轻日"（**经验值（推断）**）：站数 ≤2、单点停留 ≤2h、0 个需预约项、不跨区、不设主锚点。
- **插入频率**（**经验值**）：行程 ≥5 天至少 1 个；≥9 天每 4–5 天 1 个；以徒步 / 户外为主的行程按 7–10 天 1 个。
- **排布节奏**（**经验值**）：两个"低产日"（抵达 / 移动 / 返程）不得相邻；完整日连续 ≤2 天，第 3 天必须插 1 个中 / 低日；参考 7 天节奏 `完整 / 完整 / 中 / 休息或移动 / 完整 / 轻`。
- 时区、国际到达入境缓冲、首末日时段：见 itinerary-craft §1.5。

## 2 优先级分层与砍序

三档必须落到数据模型里，否则后期分不清谁能让路（**硬线**：能表达"不能动"的只有 `locked`）：

| 档 | 落点 | 说明 |
|---|---|---|
| 必去 | item + `locked:true` + `notes` 带 `[锚点]` | 锚点；重算时其它项绕它排 |
| 想去 | item，不锁，不加前缀 | 默认层，可移动 |
| 可选 | 二选一：① 落进当天 `items` + `[可跳过]` ② 只进地点库、`status:'candidate'`、不落 `items` | 时间不够时的第一批牺牲品 |

- **分档只问一句**："回程班机上会不会真的遗憾？"只有答"会"的升为必去并加锁（**经验值**）。这句必须问用户，不许替他分档。
- **必去容量校验**（**经验值（推断）**）：必去数 ≤ 可用整天数 × 2，且**每天主锚点 ≤1**。超出 → 在骨架阶段就报"装不下"，别排完才发现。
- **主锚点降级**：完整日的主锚点是 1 个 60–120min 的核心点；同一天出现第 2 个同类核心点（两个博物馆、两座观景台）时，第 2 个降为可选（**经验值（推断）**；站数上限见 itinerary-craft §1.2）。
- **先写天标题再上锁**（**硬线**）：当天有锁定项时 `set-day-title` 与 `remove-day` 被拒（`src/domain/patch.ts:810,1018`）。要写"D3 工作日｜会场"这类标题，先 `set-day-title`，再 `set-item-lock`。

**砍序阶梯（时间不够先砍谁）** —— 只在**未锁定**集合内执行，命中即停，**一轮只砍 1 站**（全为**经验值（推断）**）：

1. `notes` 带 `[可跳过]` 的项；
2. 当天已有"同类替代"的项（两个博物馆 / 两条老街 / 两个观景台，只留一个）；
3. 删掉后**当天总在途下降最多**的绕路点（用 `legs` 求和比较，不靠感觉）；
4. 与其它天主题重复的项（跨天去重）；
5. 停手——剩下全是必去 / 锁定 / 需预约项，交 §5 让用户二选一，绝不自己动手。

砍完立刻重跑该天 `travel_day_rebuild_legs`，再复核 §4 的判据有没有被顺序变化破坏。

## 3 同一堆点怎么排序

| # | 判据 | 数字 / 条件 | 标签 |
|---|---|---|---|
| 1 | 先定锚点，再切段 | 固定时刻锚点按 `startAt` 升序；N 个锚点把一天切成 N+1 段；每段独立聚类，不跨段连点 | 经验值（推断） |
| 2 | 段容量 | 段容量 = 下一锚点 `startAt` − 上一锚点 `endAt` − 已测转场；段内"停留和 + 最小转场" ≤ 段容量；不够就放 0 个点，不硬塞 | 经验值（推断） |
| 3 | 同区多点 → 单向环线 | 绕片区质心的方位角单调；自检 = 顺序连线**不自交**（一自交就是折返） | 经验值 |
| 4 | "先远后近"只用于放射状日 | 仅当远点单程 ≥ 当天总在途 50%，或远点是户外 / 受午后影响；环线日不适用 | 经验值（推断） |
| 5 | 锚点之间不可行 | 要在两锚点间填点就得"往返回头"（该点连线与整体走向反向）→ 判当天不可行，把那点挪到另一天 | 经验值（推断） |
| 6 | 餐位落点 | 每餐必须落在当天活动簇的 10min 移动圈内；落不进就写"当天簇内自由用餐"并留 60–90min | 经验值（推断） |
| 7 | 交付格式 | 每天输出"主题 + 锚点 + 段划分 + 顺序 + 顺序理由"，让用户看得出为什么这么排 | 经验值 |

- 聚类半径、一天一区、住宿到首站见 itinerary-craft §1.3；缓冲与用餐窗口见 §1.4。**第 3 条**比 §1.3 的"≥2 次方向反转"更强：有坐标就能自检，不用心算。

## 4 精力曲线

| 判据 | 数字 | 标签 |
|---|---|---|
| 高耗锚点配额 | `plannedDurationMinutes` ≥120 的锚点每天 ≤2 个，且**不得相邻** | 经验值 |
| 连续在脚上限 | 连续步行 / 站立 ≤3.5h 必须插 ≥30min 坐下块；全天在脚 ≤8h；带儿童或 60 岁以上 ≤6h | 经验值 |
| 午后低谷 | 13:00–16:00 只放低耗块（咖啡馆 / 公园 / 商场 / 馆内），**不排主锚点**；人体午后低谷约在 14:00–16:00 **[二手]**，13:00 起手是本手册收紧的 | 经验值（推断） |
| 高能 / 恢复交替 | 用强度标签判：连续"高" ≤2 天，第 3 天必须 ≤"中"；移动日次日 ≤"中" | 经验值 |

| 个人峰谷 | 用户自称早鸟 / 夜猫时主锚点随之移（早鸟→上午第一小时，夜猫→10:30 后）；没声明按默认上午 | ⚠ 需问 |

## 5 必去冲突怎么取舍与呈现

先分型，型决定走哪条梯子（全为**经验值（推断）**）：

| 型 | 判据 | 怎么办 |
|---|---|---|
| 容量型 | 两个必去点都没有固定时刻，只是当天装不下 | ① 能分到两天（都无固定时刻）→ 分，各自成簇；② 不能 → 交用户二选一 |
| 时刻型 | 放票 / 预约 / 班次时刻撞车 | 两固定时刻之差 < "前一项停留 + 转场 + 15min" → 判"当天不可能同做"（转场用 `travel_route_plan` 查） |
| 距离型 | 两点地理上不能同日 | 查真实单程；单程 ≥ 当天可用窗口 50% → 判"不可同日"，**不说"可以试试"** |

- 取舍排序（**经验值（推断）**）：稀缺性（放票窗口短 / 限流）> 不可替代性（只在当地有）> 同行人一致性 > 成本。
- **绝不替用户解掉 `locked` 项**；给选项前先把真实里程与时长查出来（**硬线**：锁定项不可移动、不可改时、不可删除）。

呈现模板（照抄，四列齐全 + 1 个默认推荐；模板里的数字都只是示例，落地换成你查到的真实数字，放票窗口为**经验值**，见 itinerary-craft §3.3）：

```
【冲突】D3 上午：A（需预约，放票 7 天）与 B（固定 10:00 场次）只能选一个
选项甲：保住 A —— 放弃 B；代价：当天少 1 个核心点，B 需改到 D4（多 40min 在途）
选项乙：保住 B —— 放弃 A；代价：A 的放票窗口 3 天后关闭，本周无法补
默认推荐：甲（B 可改天，A 不可）
回一个「甲 / 乙」即可，其余不动。
```

四列 = 能保住什么 / 必须放弃什么 / 代价 / 能否补救；代价必须是查来的真实里程与时长。

## 6 韧性与备选（换一处不用重排全天）

- **备选池规模**（**经验值**）：每个"必去且开放状态不确定"的点，同区备选 ≥1；每天备选池 ≥1（bail 退出路线同法）。
- **合格备选五条**（**经验值（推断）**）：① 在当天簇内（步行 ≤1.5km 或车程 ≤20min）② 停留时长与原站差 ≤30min ③ 无需预约 ④ 室内或半室内 ⑤ **它自己的开放状态同样要核实**——"备选当天也关着"是最差结果。
- **换位不变性**（四条同时满足才算合格，**经验值（推断）**）：替换后当天首项 `startAt` 不变 + 当天顺序不变（原地替换）+ 只重跑**该天** `rebuild_legs` + 当天总停留变化 ≤30min。不满足 ⇒ 备选不合格，重选。
- **换手流程**：`remove-item` → `add-item`（`notes` 一次写全）→ 该天 `travel_day_rebuild_legs`（**硬线**：`notes` 只在 `add-item` 时可写，`src/host/patch-input.ts:398-407`）。
- **标记区分**：`[闭馆备选→dX]` 是原地补位同一站（本文件新增）；`[雨天替代→dX]` 是把室外换成室内（见 itinerary-craft §4.3-5）。前缀只是给人看的。
- **备选之间要跨两个轴**（**经验值**）：价格档 × 体力档。三个同价同类选项等于没有选择；池子里要有一档是"今天大家累了"能用的。
- **每天一行 late-cut**：固定写"迟到 >1h → 先砍 X，再砍 Y"，进交付摘要与导出行（**经验值**）。
- 方案分支不可用（`scenarios` 只有 `main`），别承诺"雨天版方案"：见 itinerary-craft §4.3-5 与 patch-ops。

## 7 特殊行程结构（多日徒步/朝圣、高原、潜水）

**多日徒步 / 朝圣**：容量单位从"每天几个点"换成"**每天多少公里 + 多少爬升**"。

| 判据 | 数字 | 标签 |
|---|---|---|
| 常规徒步日 | 15–25 km/日；一份公开排法里宽松版为日均 15 km **[二手]** | 经验值 |
| 骑行日 | 60–80 km/日 | 经验值 |
| 起点城市 | 先留 1 天调时差，第一天只走短程 | 经验值 |
| 分段结构 | 前段 / 移动休息 / 后段 / 终点延伸段；终点后不直接接回程 | 经验值 |
| 表里必须带星期 | 周末补给与乡镇班车都会变少 | 经验值 |
| 住宿层级 | 庇护所 / 民宿 / 旅馆三档分别给设施 | 经验值 |

- ⚠ **地图步行时长不能当里程来源**：`travel_route_plan(mode:'walking')` 用的是城市步行速度常量（**硬线**，见 itinerary-craft §1.1），跨天长距离会严重低估；必须用官方线路里程 / GPX 或用户口述，并标"经验值 / 未核实"。爬升同样查不到，只能问用户或取自 GPX。
- 先定大致路线，再按体力与假期切 stage；多给 2–3 条"bail"退出路线（**经验值**）。
- 休息日频率按 §1：徒步 / 户外为主的行程按 7–10 天 1 个。
- 跨城赶路日的 4–6h / 8h 判据只管机动车，见 itinerary-craft §5。

**高原**（**权威出处**：CDC Yellow Book 2026）：

- 不要一天内从 <1,200m 直升 2,750m 睡眠海拔；到 2,450–2,750m 先适应 2–3 晚。
- >3,000m 后**睡眠海拔每天 ≤+500m**；每再加 1,000m 多留 1 晚。
- 到达头 48h 只轻度活动、不饮酒；症状加重时**下撤 ≥300m** 即缓解。
- 孕妇睡眠海拔不建议 >3,050m；儿童与成人同样易感。
- 编排落点：逐天睡眠海拔单调上升，**不安排"零适应天"的高海拔段**；适应日写成"轻度活动"的整天。
- 禁忌人群（不稳定心绞痛、重度 COPD、90 天内卒中 / 心梗、重度肺动脉高压、镰状细胞贫血等）**只写"出发前问医生"，不给结论、不给药**（见 §11）。

**潜水**（**权威出处**：DAN 指南，经 PADI 转述）：

- 单次免减压潜水后 ≥12h 才能飞；多次 / 多日 ≥18h；需减压停留 ≥24h。
- 潜水后 24h 内不上 3,000m 以上（不登山、不索道、不跳伞）；4–6h 内不做剧烈运动。
- 同一趟既有山又有水 → **先山后水**。
- 编排落点：潜水日与"飞行日 / 上高原日"之间按上面的小时数留空，并在 `set-day-title` 里标成"余量日"。

| 特殊约束（饮食 / 宗教 / 高原 / 潜水） | 禁忌的**严格程度**（素食含蛋奶吗？清真要认证吗？过敏原 + 严重程度 + 是否自带上药）；有高原 / 潜水禁忌疾病吗 | 特殊餐食最迟**起飞前 24h** 申请；轮椅 / 医用氧气 / 服务犬最迟**航班离站前 48h** 提出，并在办票截止前 **2h** 到机场；高原与潜水按 §7 | **权威出处**（国航特殊餐食页；民航局《残疾人航空运输管理办法》） |
| 儿童与预算口径 | 确切年龄（车票按乘车日期算）；能连续走 >30min 吗；要午睡 / 推车吗 | 铁路：未满 6 周岁不单独占席可免费、每成人限带 1 名、须购票时申明；6–14 周岁儿童优惠票；未满 14 周岁须随同成人。航空：未满 2 周岁 = 成人普通票价 10% 且不占座；2–12 周岁国内 = 50% 且免机场建设费；婴儿票每航班约 5% **[二手]**。学龄前：主要停靠 2、items ≤4、12:00–14:30 午睡不排点、跨城驾车 ≤4h（后者见 itinerary-craft §5） | 票务为 **权威出处**（12306 购票须知；民航局航旅指南）；排程数字为 **经验值（推断）** |
| 多旅客在场窗口 | 每天的在场名单：谁不在（absent）、谁在但没空（unavailable） | 不在的人**不排、不点名**；人在但没空 → 给他**一条完整并行轨道**（点名地点 + 时间块 + 汇合方式），不写"自由活动"；群体锚点若只能落在有人缺席的日子，必须点名"谁缺席 + 被哪条硬约束逼的" | 经验值 |

- 前三行 = 画像研究认定的"会改变参数"的三类；第 4 行来自专项调研，同样改变逐日安排。
- **写不进模型，只能落 `notes` 与交付摘要**：`travelers` 只有 label/interests，没有逐日在场字段；`constraints[]` 与无障碍字段没有写入路径。`[并行]` / `[缺席]` 前缀也只给人看。
- **写得进但不生效**（**硬线**）：`avoid` / `interests` / `maximumWalkingMinutesPerLeg` 除解析、存储外没有任何读取方——不告警、不重排、不影响搜索。对用户只能说"**我已按此设计**"，不能说"插件会按它校验"。
- **不进**本表的三类：情侣 / 朋友专属参数、独自旅行的夜间安全专门条款、商务顺带游统计与差旅政策——理由见 §11。

## 9 交付前的设计层体检

**先跑 `travel_itinerary_validate` 把 error 清零**——机械层（字段 / 坐标 / 重叠 / 缺 leg / 超载 / 预算 / 过期）不合格的行程不必做设计体检。设计层**不重复报这些**，只报结构问题（告警清单见 alerts.md）。

| # | 问 | 判据 | 命中后 |
|---|---|---|---|
| 1 | 一天说得出一句主题吗（一个片区 / 一条线 / 一件事）？ | 说不出 = 拼盘 | 重排或砍点 |
| 2 | 顺序连线自交几次？ | ≥1 次 = 折返 | 按 §3 重排 |
| 3 | 连续高强度几天？ | 连续 ≥2 天"高" | 按 §4 插恢复日 |
| 4 | 每天 ≥1 餐落在当日簇 10min 圈内？ | 不满足 | 按 §3 第 6 行改 |
| 5 | 完整日无计划块 ≥90min？ | 不够 | 数字见 itinerary-craft §1.2 |
| 6 | 一天几个核心点？ | ≥2 个 ⇒ 标"这天其实是两天" | 降级或拆天 |
| 7 | 首末日按日型排了吗？移动日锚点 ≤2 吗？ | 否 | 回 §1 改 |
| 8 | 每个 `locked` 项配了同区备选吗？ | 没有 | 按 §6 补 |
| 9 | 交付话术守纪律吗？ | 一次最多 **3–4 条**可选建议；计划本就完整就直说"挺完整" | 不硬凑、不替用户重排（**经验值**） |

**对抗式收尾**（**经验值**）：用执行者视角反读一遍，专挑三类硬伤——**时刻荒诞**（凌晨三点参观、最后入场前 10min 才到）、**量荒诞**（一天开 18h、一天走 30km）、**链条断裂**（到不了下一个补给 / 加油 / 充电点、末班车已过）。命中任一条先改再交付；判断标准不是"清单跑完"，而是"**这份行程你敢照着走吗**"。连锁可行性不在数据里 → 列为待确认，不当断言。

## 10 预订清单与截止日（四列 + horizon 重排）

交付时把待订项写成四列，一条一行（**经验值**）：

| 类别 | 提前量 | 具体截止日 | 在哪订 |
|---|---|---|---|
| 例：跨城高铁 | 约 15 天 | 出发前 15 天（= 20XX-XX-XX） | 12306 / 官方 App |

- **重排规则**：按"距出发天数已经吃不下这条提前量"的行优先列在最前，**余量最小的排第一**。这是每次交付时**现算**的（今天 vs 出发日），不要在文档里落成一个固定字段——插件没有这个字段。
- **查不到提前量的行，报"记录缺字段"**，别默认它"在窗口内"或"在窗口外"（**经验值**）。
- **不把"自己也订不到"的备选当解决方案**：一个订不到换成两个订不到，还把计划报成"已修好"。临近出发时，"把活动挪到更晚的一天"本身就是买时间的手段。
- 提前量的具体数值与三档倒推（立即订 / 1–3 个月 / 2–4 周）：见 itinerary-craft §3.3，**全部为经验值，以官方放票窗口为准**。
- 插件边界：查不到放票时刻、余票、能否订到；没有预订状态字段 → 截止日只能落在导出文档与 item `notes`（且 `notes` 只在 `add-item` 时可写）。

## 11 不要写进 skill 的

| 候选 | 为什么不加 |
|---|---|
| **实时天气接入 + 天气驱动自动重排**（含 ≥32°C 停止户外这类阈值表） | 插件查不到天气；接 API 等于引入外部依赖与时效责任。现有口径是"用户主动提到才处理"，够用；写进去只会让 agent 复述无人验证的数字 |
| **任何模型记忆型"事实表"**：营业时间、门口票价、城市必去榜、闭馆日常量表 | 一定会过期，且违反"不编造高德没给的事实"这条红线。承接机制已完整：`notes` + `⚠ 待确认：…` + `—` |
| **在真实路线时长上乘全局系数**（如徒步 ×1.5） | 我们有真实路线数据；系数会与缓冲重复计算，还把查来的数字变成估的，正好毁掉本插件相对纯 prompt 方案的核心优势 |
| **评分 / 排队时长驱动的排序** | 无数据源；且会诱导用户以为"高分先排"。替代：顶流点排开门时段 + 待确认清单 |
| **无障碍设施的技术几何**（GB 50763 的坡道净宽 1.00m、1:12 坡、平台 ≥1.50m 等） | 插件查不到目的地的真实坡度与净宽，写进正文等于诱导 agent 编造"这个景点无障碍达标"。只留"现场确认"占位符 |
| **高原药物与剂量**（乙酰唑胺 125mg bid、地塞米松…） | 属医疗建议，超出 skill 边界，剂量必须由医生给。只写"上高海拔前咨询医生 + 下撤优先" |
| **自动预订 / 下单等外部动作** | 越权且不可回滚；放票时刻与余票也查不到。现有做法（清单 + 提醒）已覆盖 |
| **画像类刻板印象参数**（情侣纪念日、独行夜间安全专门条款、bleisure"68% 的差旅会延长、平均 2.3 晚"） | 无可靠出处、无法判定，或推不出任何排程参数 |
| **用 `constraints[]` / `accessibilityNeeds` 表达约束** | 没有任何写入路径，承诺了就是骗人；替代只能是 `locked` + `notes` 前缀 |
| **给"带儿童每天最多 N 个景点"写死一个数字** | 与 itinerary-craft §1.2 的 `relaxed` / 儿童午后规则重复，且没有权威出处，写死就会被当成事实 |

> 表内数字只用于说明"为什么不加"（天气阈值、全局系数、GB 50763 几何、乙酰唑胺剂量、68% / 2.3 晚），其中 68% / 2.3 晚为 **[二手]**，其余取自现行标准与现行医疗惯例，**都不是本 skill 的内容**。
