# 赶路日在地图上的路线显示 — 优化方案与实施记录

状态：**已实现（0.12.0，2026-09-21）**，P1/P2 已落地并有真机与单测证据，P3（静默补全）未做；实施记录与评审结论见 §七。

本文基于真实高德地图（用你环境里的 JS Key）对**你这份 14 天行程**的实测截图与逐日测量。

---

## 一、现状：赶路日在地图上到底画了什么

实测（`.verify/map-drive-days.mjs`，真实 AMap，全程模式）：

| 场景 | 今天画出来的是 | 问题 |
|---|---|---|
| **有记录 leg 的赶路日**（D1 北京→西安 1077 km） | 一条**细虚线**（天安门广场→回民街 的站点顺序线） | 与"市内两站之间 300 米"的线**完全同一种样式**，看不出这是 12 小时 38 分的高速 |
| **只有标题的赶路日**（D2/D3/D7/D12/D14） | 同样是一条细虚线，而且是**借相邻天的端点**连出来的 | 线"属于"前一天，语义错位；没有里程/时长 |
| **当天模式下打开某个赶路日** | **一条线都没有**（该天只有 1 个站，`buildRouteSegments` 需要 ≥2 个点） | 用户最想看的"这一天怎么开"，地图上空的 |
| **完全没有安排地点的赶路日**（转场两端只有城市名） | **什么都没有**：`transitPath` 需要两端坐标，纯名字 → `[]`；`buildGroups` 也因该天没有带坐标内容而跳过 | 新行程里"只写 西安 → 成都 740km"的那一天，地图上不存在 |
| **有真实路径的转场**（手动「记为转场」+「用高德重算」后） | **实线 + 真实道路** ✓ | 需要**每天点两次**，5 天就是 10 次操作 |

补充：0.11.4 已经把"转场"画成实线、端点画成方块 ✓，但那要**先有转场**；而"只有标题、没有地点、没有转场"的赶路日，正是现在最缺的一类。

**一句话**：地图把"跨城赶路"和"市内挪窝"画成同一种线，而且只要端点没有坐标（只有地名），连这条线都没有。

---

## 二、目标

1. **赶路日一定有路线**，从有记录的 leg、到只有标题、到只有两个城市名，逐级降级都能画。
2. **一眼能分辨**：跨城赶路 ≠ 市内移动。
3. **能看出这条路的份量**：里程与时长直接标在路上。
4. **不需要手动点两次**：真实路线应当能一次补全（或自动）。
5. 不违反已有约定：**不偷偷启动高德容器**（那会弹出桌面窗口）；有 Web 服务 Key 时走 HTTPS，没有就画估算线并提示。

## 三、方案

### 3.1 路线来源的四个等级（逐级降级，永远有东西可画）

| 等级 | 数据 | 线型 | 端点 | 标签 |
|---|---|---|---|---|
| L1 真实路线 | 转场带 `polyline`（高德 Web 服务 `/v5/direction/driving` 的路径） | **实线**，线宽最大 | 起/终方块 | `驾车 · 723 km · 8 小时 12 分` |
| L2 已规划无路径 | 转场有里程/时长但无 polyline（CLI 结果），或当天一段 ≥100 km 的主导 leg | **实线**（两端直连） | 起/终方块（转场）／该站自己的水滴（leg） | `驾车 · 723 km · 8 小时 12 分` |
| L3 只有标题 | 从标题解析出 A→B + 里程，端点用该天自己的站点，其次借相邻天 | **长虚线** | 借来的站点，不再另加方块 | `驾车 · ≈723 km · 按标题估算` |
| L4 只有城市名 | 两端都只有名字，**由 Host 地理编码**（`/v3/geocode/geo`）得到城市中心坐标 | **长虚线** | 同上 | `驾车 · ≈723 km · 按标题估算` |

L3/L4 都**不需要用户安排任何地点**；L4 需要一次地理编码（HTTPS，不开窗口）。

端点画法说明：**方块只属于转场端点**（L1/L2）；L3/L4 的端点本来就是别的日子里的站点，那些站点已经以自己的水滴出现，再叠方块只是噪声（评审 finding 6 的取舍，见 §七）。

### 3.2 需要改的地方

**客户端（P1，纯刷新即可生效）**
1. **派生路线**：新增纯函数 `driveRoutes(days)`——对每个"标题声明跨城"的日子产出一条路线（L3/L4），坐标取自 `buildTransfers` 已经算出的相邻端点；**没有任何地点的那一天也要产出一条**（用相邻天的端点）。
2. **样式分层**：`.trv-drive-line` 实线（L1/L2）/ 长虚线（L3/L4），线宽 > 市内虚线；`buildGroups` 让"有派生路线的天"也进入绘制集合（现在无坐标就会被跳过）。
3. **路线标签**：线中点一个胶囊（复用现有"名字在缩放 ≥6 显示"的阈值），L1/L2 显示实数据，L3/L4 带 `≈` 与「按标题」。
4. **当天模式**：把该天的路线放进 `overlaysByDay`，`聚焦当前天` 与自动 fit 都框住整条路（单站日现在框不出任何东西）。
5. **图例/差异**：地图左下角一句说明（`实线=已规划 · 虚线=按标题估算`），与站点名字同一套显隐规则。

**Host（P2）**
6. **端点地理编码**：`setDayTransit` 在两端只有名字时，先用 Web 服务 `/v3/geocode/geo` 把城市名解析成坐标写回端点（有 Key 时）；没 Key 时保持只有名字（地图上退到"无坐标 → 不画线"，但面板仍显示这条转场）。
7. **批量补全**：新 HTTP 路由 `POST /fill-transits`（与 `/rebuild-legs` 同构，面板按钮直接调，**不经过模型**）：把"有标题、无转场"的赶路日一次性规划并落盘（REST 优先，CLI 兜底），返回每天结果。面板在行程头部与地图角上各放一个入口：`补全 5 天路线`。

**可选（P3）**
8. **静默补全**：配置了 REST Key 时，首次进入全程模式自动补全一次（每次会话最多 6 天，写回行程，不弹窗）；没有 Key 时只在按钮上提示"需要配置 Web 服务 Key，或启动高德容器（会打开地图窗口）"。

### 3.3 地图上的样子（示意）

```
   北京 ●D1 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄ 西安
              〔京港澳 · 1077 km · 12 小时 38 分〕   ← L1 实线 + 标签
   西安 ┄┄┄┄┄┄┄┄┄┄┄ 成都
        〔≈723 km · 按标题〕                      ← L3 长虚线 + 估算标签
   丽江 ●D5 ─  ─  ─ 大理                          ← 市内：细虚线，无标签
```

## 四、取舍与备选

| 备选 | 为什么不选 |
|---|---|
| **只把"只有标题"的线加粗**（不改数据） | 仍然没有真实道路，也解决不了"完全没地点"和"当天模式没有线" |
| **读视图时自动为每天规划**（不落盘） | 每次打开面板都要问一次高德，30 天行程浪费配额；而且没 Key 时会想开容器。改为"预览免费（L3/L4），落盘才规划" |
| **让用户先补地点再看路线** | 这正是你要摆脱的约束：赶路日不该逼人加地点 |
| **把 leg 与 transit 彻底统一成一张移动图** | 长期方向，另开一轮；本方案的 L1–L4 是它的过渡形态 |

## 五、影响面与分期

- **P1（本轮，客户端）**：`driveRoutes` + 线型分层 + 路线标签 + 当天模式 fit + 图例；改动集中在 `src/client/index.ts`，**刷新页面即生效**（无需重启）。
- **P2（本轮，Host）**：端点地理编码 + `POST /fill-transits` + 面板按钮；动 Host → **需要重启**。
- **P3（可后置）**：静默补全、Markdown 导出把赶路日画成 起→终 + 里程。

验证方式：
- 真机（真实 AMap + 你的行程）：全程模式逐日截图；当天模式打开 D2/D7/D12 截图；路线标签与线型的像素级检查。
- 单元测试：`driveRoutes`（有地点/只有标题/只有名字/无地点四类）、线型分层、fit 集合包含派生路线。
- Host：地理编码的解析与缓存、`fill-transits` 的批量结果与失败回执。

## 六、需要你定的三点

1. **L3/L4 的估算线要不要默认画**？我倾向**要**——地图上先看见这条路，比"什么都没有"有用得多；代价是它与已规划路线必须明显区分（长虚线 + `≈` + 「按标题」）。
2. **要不要自动补全**（P3，配了 Web 服务 Key 时静默补全一次）？我倾向**先不做**，这一轮只做「补全 N 天路线」按钮，等你看过效果再决定是否自动化。
3. **地理编码（L4）需要城市名的精度到什么程度**？`成都` → 市中心；如果你的行程里写的是 `成都东站` 这类，我会先试 POI 搜索再退回地理编码。

### 7.4 已知限制（本轮不改）

- 估算线（长虚线）是标题两端点的**两点直连**，不代表真实道路；点「补全 N 天路线」或「记为转场」+「用高德重算」之后才会变成真实路径。
- 相邻两个「只有标题、且标题地名都匹配不到站点」的赶路日，仍可能借用同一对端点，画出两条同形的估算线。
- 起/终方块只属于转场端点（L1/L2）。
- 同一条判据在 client / host / domain 各有一份实现：客户端 bundle 只能 `require("react")`，不能与宿主共享值模块，所以靠注释 + 三处测试约束，改一处必须同步另外两处。
- `POST /focus` 仍要求当天有带坐标的站点，不认转场端点；L4 只走地理编码，没有「先 POI 搜索」的兜底（`成都东站` 这类会更准）。
