# 右侧栏 v5 设计（已批准 · 实现中）：一条连续的行程卷轴

承接 `docs/sidebar-v4-design.md`。本文只做设计，不含实现；**批准后**再动代码。
观测版本 DSH `0.1.6-alpha.1`，素材是你那份真实行程 `北京→丽江 自驾婚纱之旅`（14 天）。

---

## 0. 你提的问题

> 行程和时间的显示形式看起来还是有点不直观……只能一天一天看，看着就很乱、不直观、不整体。

拆成三件事：

1. **看不到整体**：一次只能看一天，14 天的行程要点 14 次；「这趟旅行长什么样」没有任何一处能一眼看到。
2. **行程与时间是两套东西**：日期栏给的是 D3/09-26，时间轴给的是 09:00 和一段驾车，地图给的是另一套编号；三者各自表达「第几天」，没有合并。
3. **真正的行程信息藏在标题里**：你这份行程的骨架是「北京→西安 1077km」「西安→成都 723km」——它写在**天的标题**里；
   而时间轴的 leg 只有 10 天有，另外 4 天（d2/d3/d4/d7/d9/d10/d13/d14 中的 8 天）只有 1 个站点、**没有 leg**，
   于是「赶路」这件事在时间轴上根本不存在。这就是「割裂」的来源。

数据实测（你的行程）：

| 项 | 数值 |
|---|---|
| 天数 / 站点数 | 14 天 / 32 站 |
| 有日内交通段的天 | 10 天（共 21 段） |
| 只有 1 站、无交通段的天 | 8 天（d2 d3 d4 d7 d9 d10 d13 d14） |
| 已记录行驶时长合计 | 38.7 小时 |
| 停留时长 | **全为 0（未填写）** |

---

## 1. 目标与非目标

**目标**

- 一屏之内能看出「这趟旅行的形状」：哪几天在赶路、哪几天在玩、哪天休整、哪里有告警。
- 行程与时间合并表达：天 == 一个时间区块（日期 + 里程 + 行驶 + 站点），段 == 两点之间的时间代价。
- 不再需要「一天一天点」。

**非目标（本轮不做）**

- 不做跨天拖拽、不做甘特图式的小时级缩放。
- 不改 Host 数据模型（本轮只读现有字段；「停留为 0」这类数据问题单独处理）。
- 不做 PDF / 打印导出。

## 2. 三个方案

### 方案 A：连续行程卷轴（推荐）

去掉「一天一页」，时间轴变成**一条连续的纵向卷轴**：14 天首尾相接，日期标题吸顶，天与天之间用**城际段**连接。

```
┌ 行程条（顶部，可收起）────────────────────────────────────┐
│ D1 ▓▓▓▓▓  D2 ▓▓▓  D3 ▓▓▓ … D14 ▓  ← 14 格强度条 + 告警点  │
└──────────────────────────────────────────────────────────┘
╭ D1 · 09-24 周四 · 北京 → 西安            行驶 12h38 · 1077km · 2 站 ╮   ← 吸顶
│ 12:00 ●  天安门广场                                        [图]  │
│          风景名胜 · 东长安街                                     │
│   🚗 驾车 1077.1 km · 12 小时 38 分                     待重算    │
│ 次日 00:30 ●  回民街                                            │
╰──────────────────────────────────────────────────────────────────╯
   │  ← 城际衔接（虚线继续）
   🚗 西安 → 成都 · 723 km · 约 8 小时（未记录，来自当天标题）
╭ D2 · 09-25 周五 · 西安 → 成都            未记录交通 · 1 站        ╮
│ …                                                               │
```

**要点**

1. **日期标题吸顶**，始终知道「我在第几天」；标题里直接放行程骨架：`D3 · 09-26 · 成都 → 丽江｜到站 821km`（取自天标题），右侧是该天合计：`行驶 9h20 · 821km · 1 站`。
2. **天标题即行程**：你行程里「赶路/到站/休整」这些词在天标题里，直接显示出来，不再只显示 `D3 09-26`。
3. **城际段显性化**：两天之间插入一段衔接行。有 leg 用它；没 leg 但标题里有里程（如「成都 → 丽江｜到站 821km」）就按标题显示并标注「来自当天标题」；都没有就写「未记录交通」并给一个「重算」入口。
4. **当天时间轴不变**（时间轨 + 卡片 + 缩略图 + 拖拽），只是不再需要翻页。
5. **日期栏升级为目录**：每行 `D3 09-26 ▓▓░░ 821km`，含强度条与告警点；**滚动联动**高亮当前可见天，点击滚动到那天。
6. **跨零点**：像你 D1 的「回民街 00:30」实际是次日凌晨，卷轴里显示为「次日 00:30」，不再看起来像时间倒退。

**代价 / 风险**

- 14 天连续渲染：你的行程约 56 行（14 标题 + 32 站点 + 10 段），约 5 屏，可接受；更长的行程需要虚拟滚动（>200 行再做）。
- 吸顶标题 + 滚动联动需要 `IntersectionObserver`（或滚动位置计算），是新增的交互复杂度。

### 方案 B：只加「总览条」，时间轴仍逐日

顶部加 14 格强度条（每天一格：行驶占比 + 告警点），点击跳天；时间轴保持现在的逐日翻页。

- 优点：改动最小，一周内可完成。
- 缺点：**没有解决「行程与时间割裂」**，只是给了张目录；你仍然要一天天点。

### 方案 C：行程串（route ribbon）

把整趟行程画成一条「串」：城市/站点是节点，段上写方式与时长，按天分组；不显示具体钟点。

- 优点：整体感最强，像地铁线路图。
- 缺点：丢掉钟点，「时间」这一半信息被牺牲；且与地图的全程视图重复。

## 3. 推荐：A +（B 的强度条并入日期栏）

| 决策 | 选择 |
|---|---|
| 时间轴形态 | **连续卷轴，取消「逐日」模式**（少一个模式 = 少一层割裂）；单天行程自然退化成现在的样子 |
| 导航 | 右侧日期栏（带强度条）负责跳转与定位；吸顶日期标题负责「我在哪」 |
| 城际段 | 渲染在**两天之间**；数据缺失时如实标注，不编造 |
| 地图 | 保持「当天 / 全程」；**本轮即做**滚动联动（当前天满色、其余淡化 + 「聚焦当前天」） |
| 停留时长 | 数据里为 0 时不显示该合计（现在全为 0，显示出来只会误导） |

### 3.1 日期栏（目录 + 强度条）

```
D1  09-24  ▓▓▓▓▓▓▓▓▓▓  ·           ← 行驶 12h38 / 强度满格
D2  09-25  ░░░░░░░░░░  未记录       ← 无 leg：整格留白 + 灰字提示
D5  09-28  ▓▓▓░░░░░░░  175km
D14 10-07  ░░░░░░░░░░  到家/休整
```

- 强度条长度 = 当天行驶时长 / 全程单日最大值；无 leg 的天用「未记录」而不是 0（避免"这天没开车"的错觉）。
- 告警点沿用现在的黄点；当前可见天整行高亮。
- 行高维持 0.7.3 的单行 27px，14 天可直接放下。

### 3.2 天标题（吸顶）

```
D1 · 09-24 周四 · 北京 → 西安｜赶路 1,077km        行驶 12h38 · 1077km · 2 站 ⚠1
```

- 左：`D1 · 日期 · 星期` + 天标题（去掉与里程重复的部分）。
- 右：该天合计（行驶/里程/站点数/告警）。停留仅在数据存在时显示。

### 3.3 交互

- 滚动：卷轴整体滚动，标题吸顶；滚过 D1 时标题换成 D2（`IntersectionObserver`，阈值取标题高度）。
- 点击日期栏 → 平滑滚动到该天（不改地图范围）。
- 拖拽排序：不变（同日内的把手）；跨天拖拽仍不在本轮。
- 「回到今天/当前天」小按钮：滚动后一键回到当前选中的天。

## 6. 已拍板（2026-09-17）

| 决策 | 结论 |
|---|---|
| 时间轴形态 | **取消「逐日」，始终连续**（一条卷轴，日期标题吸顶） |
| 跨天行驶段 | **放在两天之间**（衔接行） |
| 日期栏 | **升级为总览目录**：强度条 + 当前天高亮 + 点击定位 |
| 地图联动 | **本轮一起做**：卷轴滚动时地图强调当前天；「当天」范围跟随当前天，另给一个「聚焦当前天」按钮 |

## 7. 实现记录（0.8.0）

### 7.1 落地形态

| 组件 | 作用 |
|---|---|
| `DaySection` | 一天 = 一个 section：吸顶天标题（D/日期/星期 + 天标题 + 行驶/里程/站数/提醒）+ 该天时间轴 |
| `TransferRow` | 两天之间的衔接行；数据来源分 `recorded`（有可用 leg）与 `title`（只有天标题里的里程） |
| `DayRail` | 目录 + 强度条（相对全程最忙的一天）+ 里程/未记录/市内 + 告警点；滚动联动高亮 |
| `TripMap` | 新增 `activeDayId`：全程模式下当前天满色、其余降到 0.3/权重 2；新增「聚焦当前天」按钮 |

新增纯函数（均已导出并测试）：`parseTransferTitle`、`hasUnrecordedTransfer`、`usableLeg`、`buildTransfers`、`dayFacts`、`dayIntensity`、`clockLabel`。

### 7.2 实测（`.verify/trip-scroll.mjs`，你那份 14 天行程）

| 项 | 结果 |
|---|---|
| 天 section / 日期栏行 | 14 / 14，整栏可滚动 |
| 吸顶天标题随滚动变化 | d1 → d7 → d12（滚到中段与末尾各读一次） |
| 跨天衔接行 | 10 条：`西安 → 成都 · 723 km`（来自当天标题）、`丽江 → 大理 · 175.1 km · 2 小时 33 分`（有真实 leg）等 |
| 跨零点标注 | `次日 00:30`（D1 回民街） |
| 日期栏读数 | `D1 1077.1 km`(100%) / `D2 未记录` / `D4 市内` / `D5 188.2 km` … |

### 7.3 与原设计的偏差（都是被真实数据逼出来的）

1. **衔接行的判定顺序改了三次**。原计划「有 leg 用 leg，没 leg 看标题」。真实数据里 leg 并不总是可信：
   - D5 一天有 3 段，第一段才是城际（175km），另两段是市内 7km/5km；
   - D7 的 leg 是 `1 m · 0 分钟`（两站同点，重建交通的占位产物）；
   - D8 里混进了属于别处的长 leg（674km 凤凰→武汉）。
   最终规则：**标题决定「是否算一次跨城」**（标题里有 `A → B` 才算），里程优先用 leg 但仅在它与标题里程相差 ≤35% 时才采信；≤1km 且 ≤10 分钟的 leg 视为占位、不参与判定。
2. **`source: 'unknown'` 被删除**：「补上这段交通」在无法判断是否真的跨城时只会变成噪音；现在只有 `recorded` 与 `title` 两种，`title` 且缺时长时给「补上时长」。
3. **停留时长全程为 0**：按设计不在标题里显示该合计（数据补上后会自动出现）。
4. **地图只在数据变化时 `setFitView`**：滚动改变强调的天时不再重新缩放（否则每滚一天地图就跳一次）。
