## 一、先定位：地图为什么「废」

这一轮最刺眼的是地图，但它不是 fit 坏了，是**框的形状错了**。

实测（截图 2652×1580 = 1326×790 CSS，DPR 2）：

| 量 | 值 | 来源 |
|---|---|---|
| 伙伴栏宽 | 593 CSS | 截图量取 |
| 地图卡高 | **205 CSS** | CSS `clamp(200px, 26vh, 300px)`，26vh×790 |
| 地图框宽高比 | **2.8 : 1** | 593 / 205 |
| 行程真实包围盒 | 100.13–116.40°E，24.85–39.91°N | `trip.json` 44 个地点，无离群点 |
| 包围盒投影宽高比 | **0.92 : 1**（近似正方形） | 经度 × cos32° / 纬度 |

**结论**：一个 0.92 : 1 的路线要塞进 2.8 : 1 的框，fit 只能把路线压成一条竖线，横向多出来的空间必然填别的地方。

- 预测：框高 205 − 88(内边距) = 117px 装 15.06°，可见经度跨度 ≈ **82°**
- 实测：截图里从左到右是 伊朗(≈50°E) → 日本(≈140°E) ≈ **90°**

两者吻合，说明 AMap 的 `setFitView` 工作正常，路线点也没错；**是框太扁，把「全程」变成了「半个亚洲 + 一小撮点」**。

附带两个真缺陷：

- **全程模式序号每天从 1 重数**（`label = String(stopIndex + 1)`）→ 地图上同时存在 14 组 1、2、3，互相压在一起；截图里就是一堆 1/2/3。
- **地图内那条深色图例**（D1–D14）压在底边与高德版权上，并且和下面的天目录**重复表达同一件事**。

### 与方案的偏差

1. **flex-wrap 改为 CSS grid。** 方案里"地图独占一行、行程列与目录共行"用 `flex-wrap` 实现时，地图的 `max-width: 560px` 会让它的 *hypothetical size* 变小，于是行程列（base `flex: 1` ⇒ basis 0）挤上了同一行，在 900px 下被压成 **156px 宽、5338px 高**，而 `.trv-body` 的 `overflow: hidden` 让它根本无法滚动——这是实测中发现并修掉的既有缺陷（v6 的 560–1079 档同样中招）。改用 grid 的两行三列显式定位后，两件事同时解决。
2. **卡片告警整条移除**（方案说"移到天头的一个 chip"）：天头本来就有 `N 提醒` chip，它的 tooltip 现在带原文，所以卡片里那行直接删掉，不新增悬挂提示。
3. **`重算交通`** 而非方案里的 `路线待更新` 作为按钮文案——按钮是动作，标记是状态：交通行上的状态标记仍写 `路线待更新`。
4. **`dayIntensity` 从"行驶秒数"改为"公里"**：条形与同一行右侧的数字必须描述同一件事，否则「≈723 km」的天会是一条空条。
5. **AMap 画布内的效果（fit、水滴/圆点实际渲染）未能在无头环境验证**——探针用的是坐标示意图（`map.enabled:false`）。布局几何已实测，画布部分需要刷新后目视一次。

## 九、0.10.2：用户目视后的两处修正

用户装上 0.10.1 后反馈两点，均已实测修好。

### 1. 时间轴节点挡住了时刻

截图里 `12:00`、`00:30` 的最后一位被节点圆点压住。量出来是几何冲突：节点 9px 宽、居中在 `--trv-node-x: 54px`，即占 49.5–58.5；而 `.trv-tick-time` 的 `padding-right: 12px` 让时刻的排版盒右边界在 `64 − 12 = 52`，**重叠 2.5px**，再算上节点 3px 的光晕，最后一格数字正好被吃掉。

改法：`--trv-node-x: 54px → 58px`、`padding-right: 12px → 18px`。现在数字排版边界在 46px，节点左沿 53.5px，**净空 7.5px**（光晕后仍有 4.5px）。探针 `v7-detail.mjs` 逐行测量每个 `.trv-tick-time` 的「内容右边界 → 节点左边界」，六个可见行全部为 7.5px；测试里也加了一条几何断言，改动一旦回退就会失败。

### 2. 详情窗口只能从左边拉伸

原来只有一个把手，且在宽栏是"左边缘"、在窄栏是"上边缘"——一个把手只能一个方向。

现在是三个：**上边缘**（只改高度）、**左边缘**（只改宽度，宽栏才显示）、**左上角**（同时改两轴，这就是"对角拉伸"）。窗口锚定在右下角，所以"往左、往上"都是变大。宽度与高度分别记忆（`detailSize` / `detailHeight`），且**未拖动过的轴不写入**，所以窗口默认仍然贴着内容高度。

用真实指针事件实测（`v7-detail.mjs`，1326px 与 420px 两档）：

| 拖动 | 1326px | 420px（底部面板） |
|---|---|---|
| 左上角 向左上 | 宽 +82、高 +72 | 宽 0（已满宽）、高 +72 |
| 左上角 向右 | 宽 −70 | 宽 −70 |
| 上边缘 向上 | 高 +50、宽 0 | 高 +50、宽 0 |
| 左边缘 向左 | 宽 +60、高 0 | 不显示（窄栏没有左边缘） |

窄栏里宽度上限按"面板当前是否已接近满宽"运行时判定（`panel.width > pane.width * 0.8`），否则会把 420px 下的满宽面板压到 0.7 倍——这是第一版实现里真实出现的 bug，探针跑出来才发现。

## 十、0.10.3：全程地图上的标记

用户目视 0.10.1/0.10.2 的三点反馈，逐条处理。

### 1. 「其他地点的颜色都看不清了」

这不是配色问题，是不透明度：全程模式下"当前天"画 0.95、其余天画 **0.3**。行程一滚到某一天，另外十三天就整片糊成灰色——而这恰好是全程视图存在的理由。

改成：其余天 **0.78**（折线 0.6、线宽 3 对 5），"当前天"靠**线宽**而不是靠把别人压黑来突出。

### 2. 「用水滴形状表示地点标记」

v7 早期为了处理"序号每天从 1 重数"，把每天首站做成水滴、其余站点做成圆点。现在按用户要求：**每一站都是水滴**。

- 每天第一站 = 当天的锚点，26px，标 `D1`…`D14`；
- 当天其余站 = 同形状小一号（22px），标它在当天里的序号；
- 坐标示意图（AMap 不可用时的兜底）画同一套形状与编号，两个界面读起来一致；
- `pinIsDot` / `dotElement` / `.trv-map-dot` 一并删除（测试里断言这些符号已不存在）。

### 3. 「在标记上显示名字」

每个标记上方一行名字胶囊。**不是无条件显示**：32 个名字铺在全国视野里只会互相压。规则抽成纯函数 `showPinNames(zoom, stops)`：

```
zoom >= 6  ||  stops <= 10
```

- 高德路径订阅 `zoomend` 读取真实缩放（用户那张截图约 6.6 级，因此放大一档即可看到名字；其实按 6 级阈值当下就会显示）；
- 示意图没有缩放，按"点数 ≤ 10"这一半规则走（当天视图必然显示）；
- 名字挂在**卡片**的 class 上（`.trv-map-labels`），不挂 AMap 的容器元素——那个元素的 class 归 AMap 所有，React 重写会抹掉它自己加的类。

顺带把示意图的顶部留白从 24% 提到 30%，名字胶囊不会再被卡片上沿切掉。

实测（`.verify/v7-map.mjs`，真实 14 天行程、示意图）：全程 32 个水滴（18 个小号）+ 32 个名字（按规则隐藏）；当天视图 4 个水滴 + 4 个名字全部显示。252 个测试通过。
