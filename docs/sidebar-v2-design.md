# 右侧栏 v2 设计：视觉重做 · 内嵌地图 · 多行程

适用范围：`skillre-travel` 右侧栏 tab（`docs/right-sidebar-ux.md` 的下一版）。
本文只做设计决策，不替代实现前的 Inspect 校验。

- 观测到的 DSH 版本：`0.1.6-alpha.1`（2026-09-15）
- 相关契约：`sidebar.right.pane.tab`（keyed/session，key = 类型 id）、`sidebar.right.tab.guide.entry`（0.1.6 新增，guide 卡片位）
- 主题 token：`--dsw-alias-bg-base|bg-layer-1|bg-layer-2|bg-overlay|border-l1|border-l2|brand-primary|label-primary|label-secondary|state-error|state-warn|state-success`、`--dsw-specific-sidebar-fill`

## 0. 结论摘要

| 问题 | 设计取向 |
|---|---|
| 1 丑、布局差 | 去掉「四段式 tab + 五条 chrome 带」；改为**行程主体 + 常驻地图卡 + 日期翻页器**，全部改用 DSH 主题 token，重建字号/间距/层级 |
| 2 地图要点开高德窗口 | 侧边栏内**直接跑 AMap JSAPI 2.0**，点位与路线即时可见；桌面高德容器降级为「精确路网」的可选出口 |
| 3 同一工作区多个行程 | `.travel/state.json` 记录**会话级选择 + 工作区默认**；工具栏新增 `travel_project_list` / `travel_project_select`；侧边栏头部加行程切换器 |

落地顺序：**P1 布局+切换器 → P2 内嵌地图 → P3 动效与可访问性**，一个 0.2.0 版本、三个可独立验收的切片。

## 1. 现状诊断（为什么丑）

现在的面板从上到下叠了 5 条横向 chrome：标题头 → 告警摘要 → 四段 tab → 日期条 → 内容；在 360px 的停靠栏里，chrome 占掉近一半高度。

具体问题：

1. **层级缺失**：11–12.5px 的字号布满全屏，标题、正文、元信息之间只有 `opacity` 差异，没有字号/字重台阶。
2. **颜色不是主题色**：全部用 `color-mix(in srgb, currentColor N%, transparent)` 推导，结果是灰糊糊的、和 DSH 其它面板不像一套东西。
3. **地图在 tab 里且不是地图**：示意图只有投影点和一条折线，信息量低于「点高的期望」，还得点按钮去拉起桌面窗口。
4. **地点卡太密**：`dt/dd` 网格 + 四个文字按钮（锁定/上移/下移/移除），窄栏里换行、挤压。
5. **没有行程身份**：头部只有标题文字，切不了行程，也看不出还有别的行程。
6. **状态元素互相打架**：状态 chip、就绪度进度条、告警计数挤在同一行右侧。

关键取舍：

- **四段 tab 取消**。行程是绝对主视图；地图常驻；「地点库」和「提醒明细」收进 `⋯` 菜单（提醒同时以角标 + 行内提示出现在行程里，因为那才是它们起作用的地方）。

## 3. 内嵌地图设计

### 3.1 技术事实（已核实）

- DSH Web 页面**没有 CSP 头也没有 CSP meta**（`curl -I /assets/*.js` 无 `content-security-policy`），页面可以加载外部脚本 → 可以引入 `webapi.amap.com`。
- `amap-gui` 自己就是用 `webapi.amap.com/loader.js` 渲染地图的，它读 `AMAP_KEY`（Web 端 JS API key）与 `AMAP_SECURITY_KEY`（jscode）。插件已经通过 `amap.webKeyRef` 解析同一个 key。
- 行程数据本身就是 **GCJ-02**，与 AMap JSAPI 期望的坐标系一致，**不需要坐标转换**。

### 3.2 架构

```text
Host                                  Client
credentials{AMAP_KEY} ─┐
                       ├─ /state ──→ view.map = { enabled, key, version:"2.0", style }
securityKey 永不外发 ──┘                     │
                                            ├─ 懒加载 loader.js（每页一次）
                                            ├─ AMap.Map(div)  ← 常驻，不随 20s 轮询重建
                                            ├─ Marker[] ← view.days[n].items[].point
                                            └─ Polyline ← 当天顺序（虚线，示意）
```

- **key 传递**：`/state` 新增 `view.map`，只带 JS key。新增配置 `amap.browserMap: 'auto' | 'off'`（默认 `auto`：有 key 就用）。
- **安全边界**：JS key 在浏览器里本就等于公开（AMap 的设计如此），`securityKeyRef` 继续只留在 Host，永不进 `/state`、永不进客户端代码。因此**内嵌地图只渲染、不发起任何 AMap Web 服务调用**（不调用 `AMap.Driving` 等需要 jscode 的插件）；真实路网仍由 Host 侧 CLI 查询。
- **路线表达**：用当天顺序连一条虚线，并在卡片角上标注「示意」；精确路网留给「在高德窗口中查看」。

### 3.3 失败与降级

| 情况 | 表现 |
|---|---|
| 未配置 key / `browserMap: off` | 直接用现有示意图，不提示（配置即意图） |
| `loader.js` 5s 超时或网络失败 | 示意图 + 一行「地图组件未加载，已退回示意图」+ 重试 |
| key 被拒（`INVALID_USER_KEY` 等） | 示意图 + 「当前 Key 未授权浏览器端使用：需 Web端(JS API) 类型并放开来源限制」 |
| 地点缺坐标 | 该点不画标记，时间轴照常显示 |
| 高德容器未运行 | 不影响内嵌地图（两者解耦） |

### 3.4 生命周期与性能

- 地图实例与 `AMap.Map` 句柄挂在 panel 组件上，卸载时 `map.destroy()`；脚本加载 Promise 挂在 Fiber 上，插件卸载即取消。
- 20s 轮询只在 `revision` 或 `activeTripId` 变化时重建标记，不重建地图。
- 日期切换：`setFitView(markers, false, [32,32,32,32])`，不做动画时也保持视口稳定。
- 宽窄布局切换（container query 跨过 560px）只改容器高度，**不重挂载**地图实例。

### 3.5 桌面高德容器的定位

`travel_map_focus` 保留，但改成 `⋯` 菜单里的「在高德窗口中查看当天路线」，用于看精确路网/街景。侧边栏的主点击行为一律是内嵌地图联动。

## 4. 多行程设计

### 4.1 存储布局

```text
<workspace>/.travel/
├── state.json                         ← 新增：当前行程指针
├── index.json                         ← 可选：切换器用的摘要缓存（派生）
└── projects/
    ├── 北京三日游-9cf2de/
    │   ├── trip.json                  ← 不变（schema v1）
    │   └── exports/
    └── 京都-4d1a77/
        └── trip.json
```

`state.json`：

```jsonc
{
  "version": 1,
  "activeTripId": "北京三日游-9cf2de",          // 工作区默认
  "sessions": {                                // 会话级覆盖（同工作区多会话互不干扰）
    "session-94393cca-…": "京都-4d1a77"
  },
  "updatedAt": "2026-09-15T09:20:00.000Z"
}
```

**「当前行程」解析顺序**（Host 侧唯一实现，UI 与工具共用）：

1. 调用方显式给的 `tripId`
2. `state.json.sessions[<本会话>]`
3. `state.json.activeTripId`
4. 最近更新的一条
5. 都没有 → 空状态

**写入时机**：`travel_project_create` → 新行程同时写会话选择与工作区默认；侧边栏切换 → 只写会话选择；「设为默认」→ 写 `activeTripId`；删除/归档当前行程 → 清空指针。

文件缺失或损坏 → 按第 3/4 步退化为今天的行为，并在下次写入时重建，**不需要迁移**。

### 4.2 为什么是「会话级覆盖 + 工作区默认」

- 纯工作区级：两个会话分别规划北京和京都时会互相抢指针，侧边栏会「跳」到对方那份。
- 纯会话级：新开会话看不到上次的行程，得手动选。
- 组合式：同一会话内切换随你；新会话默认落在工作区主线；「设为默认」把主线钉死。两种常见用法都自然。

### 4.3 工具契约

| 工具 | 变化 |
|---|---|
| `travel_project_list` | **新增**：返回全部行程摘要 + `activeTripId` + 本会话选择。用户说「第二个行程」时模型靠它选 |
| `travel_project_read` / `_patch` / `_validate` / `_export` / `_day_rebuild_legs` / `_map_focus` | 省略 `tripId` → 按 4.1 的解析顺序取**当前行程**（不再是「最近更新」） |
| `travel_project_create` | 创建后自动成为当前行程；返回值带 `tripId` |
| `travel_project_select` | **新增**：切换当前行程（等价于侧边栏切换） |

所有工具的返回值都回显 `tripId` + `title`，让模型始终知道自己在改哪一份；切换后第一次调用会返回一条 `note: "当前行程已切换为 X"`。

### 4.4 UI 契约

- `GET /state` 增加 `view.activeTripId`、`view.trips[].{dayCount,readiness,alertCounts}`。
- `POST /select { tripId }` → 写会话选择，返回新 view；`POST /select { tripId, asDefault: true }` → 同时写工作区默认。
- 头部切换器：点击展开列表，每行 = 标题 / 日期区间 / 天数 / 状态 / 就绪度 / 提醒数；当前项打勾；底部「设为工作区默认」。
- 空状态（一份行程都没有）保持现有引导文案。
- 20s 轮询发现 `activeTripId` 变了（模型在别处创建/切换）→ 自动跟随，并在头部给一次轻微高亮。

### 4.5 列表性能

现在 `list()` 要读每个 `trip.json`。几十份以内没问题；超过则写 `index.json`（每次 persist 时原子更新，含上面切换器需要的字段），读取时若 `generatedAt` 早于任一 `trip.json` 的 mtime 就重建。**`trip.json` 始终是唯一真相**，index 只是缓存，损坏即重建。

## 5. 交互细节

- **联动是双向的**：点标记 → 选中地点 + 时间轴滚到该项；点时间轴项 → 标记高亮 + 地图 `setCenter`。
- **键盘**：`↑/↓` 在时间轴项间移动，`←/→` 换天，`Enter` 展开抽屉，`Esc` 收起；标记是 `<button>`，可 Tab 到达。
- **滚动 spy**（宽栏）：时间轴滚动时左侧日期轨高亮当前天。
- **加载态**：骨架行（灰块），不再显示「正在读取旅行项目…」；错误态在面板内给一行可读原因 + 重试。
- **旅途中**：行程日期覆盖当天时，头部出现「今天 · D2」徽标，并默认落在当天。

## 7. 已拍板（2026-09-15）

1. **窄栏信息架构**：地图常驻顶部 + 行程为主体，地点库与提醒明细收进 `⋯`。
2. **内嵌地图的 key**：复用现有 `AMAP_KEY`（Web 端 JS API key），新增 `amap.browserMap: 'auto' | 'off'` 开关；`securityKeyRef` 永不外发。
3. **当前行程归属**：会话级覆盖 + 工作区默认，解析顺序见 §4.1。

### 7.1 实现前的可行性结论

内嵌地图成立的前提是「该 key 允许从 `http://127.0.0.1:<dsh port>` 加载 JSAPI」。
AMap 的 key 可能绑定了平台/来源白名单，因此实现第一步是**用真实 key 在真实浏览器里跑一次 loader 探针**。

**实测结果（2026-09-15，本机 Chrome）：通过。** 从一个无关的 loopback 端口（`http://127.0.0.1:63330`）加载
`webapi.amap.com/loader.js`，`AMapLoader.load({version:'2.0'})` 成功返回，容器内出现 1 个 canvas 与已下载的瓦片，
标记渲染正常、无 JS 报错。说明该 Key 未绑定限制性来源白名单，可以直接在侧边栏使用。

探针脚本：`.verify/amap-browser-probe.mjs`（只输出结论，不落盘 key）。
`compatibility.json` 的 0.1.6-alpha.1 条目记录了这次验证。
